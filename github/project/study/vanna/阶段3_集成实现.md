# Vanna 阶段 3：集成实现（可插拔）

> **目标**：理解"可插拔"——所有数据库/LLM 实现同一接口，Agent 只认接口。
> 学 3 个真实集成：sqlite（SQL Runner）、mock（LLM）、openai（LLM）。
>
> **核心**：Vanna 有 18+ 数据库集成 + 10+ LLM 集成，但**都是同一个接口**。学 3 个就懂全部。

---

## 三问

- **Q1 解决什么问题**：把"连哪个数据库/用哪个 LLM"变成可插拔——换数据库/模型不改 Agent
- **Q2 数据流哪一环**：两个接口——`SqlRunner`（数据库）注入 `RunSqlTool`；`LlmService`（LLM）注入 `Agent`
- **Q3 删掉会怎样**：每种库/模型一套代码，Agent 强耦合，无法换

---

## 一、两个接口（可插拔的"插座"）

Vanna 有两类可插拔：

| 接口 | 管什么 | 注入到哪 | 实现（有哪些）|
|------|--------|---------|--------------|
| **SqlRunner** | 执行 SQL（数据库）| `RunSqlTool(sql_runner=...)` | sqlite/postgres/mysql/clickhouse... |
| **LlmService** | 调用 LLM | `Agent(llm_service=...)` | openai/ollama/anthropic/mock... |

**核心**：Agent 只认接口，不认实现。换数据库 = 换 SqlRunner；换模型 = 换 LlmService。Agent 代码一行不改。

---

## 二、接口 1：SqlRunner（`capabilities/sql_runner/base.py`）

```python
class SqlRunner(ABC):
    """SQL 执行接口——所有数据库实现这个"""

    @abstractmethod
    async def run_sql(self, args: RunSqlToolArgs, context: ToolContext) -> pd.DataFrame:
        """执行 SQL，返回 DataFrame"""
        pass
```

**为什么返回 DataFrame**：统一数据结构，工具执行后 LLM/前端都好处理。

## 三、实现 1：SqliteRunner（`integrations/sqlite/sql_runner.py`）逐段

> 看一个真实数据库怎么实现 SqlRunner。核心：连 SQLite → 执行 SQL → 返回 DataFrame。

```python
class SqliteRunner(SqlRunner):
    """SQLite 实现的 SqlRunner"""

    def __init__(self, database_path: str):
        """只需一个数据库文件路径"""
        self.database_path = database_path

    async def run_sql(self, args, context) -> pd.DataFrame:
        """执行 SQL，返回 DataFrame"""
        # ① 连接 SQLite（row_factory 让结果能用列名访问）
        conn = sqlite3.connect(self.database_path)
        conn.row_factory = sqlite3.Row   # ★ 结果可按列名访问
        cursor = conn.cursor()

        try:
            # ② 执行 SQL（LLM 生成的）
            cursor.execute(args.sql)

            # ③ 判断是 SELECT 还是修改操作
            query_type = args.sql.strip().upper().split()[0]

            if query_type == "SELECT":
                # 查询：取所有行 → 转 dict 列表 → DataFrame
                rows = cursor.fetchall()
                if not rows:
                    return pd.DataFrame()          # 空结果
                results_data = [dict(row) for row in rows]
                return pd.DataFrame(results_data)   # ★ 返回 DataFrame
            else:
                # 修改（INSERT/UPDATE/DELETE）：提交 + 返回影响行数
                conn.commit()
                rows_affected = cursor.rowcount
                return pd.DataFrame({"rows_affected": [rows_affected]})

        finally:
            cursor.close()
            conn.close()   # ★ 用完关闭连接
```

**关键 3 点**：
1. `run_sql` 只做"连库 + 执行 + 转 DataFrame"——不关心 LLM、不关心工具
2. 返回 `pd.DataFrame`（统一格式，下游好处理）
3. SELECT vs 修改操作分开处理

**可插拔的用法**：
```python
# 换数据库只需换 runner（都是 SqlRunner 接口）
RunSqlTool(sql_runner=SqliteRunner("data.db"))        # SQLite
RunSqlTool(sql_runner=PostgresRunner("postgres://..."))  # PostgreSQL
RunSqlTool(sql_runner=ClickHouseRunner("clickhouse://...")) # ClickHouse
# ★ RunSqlTool 代码不改，只换注入的 runner
```

## 五、实现 2：MockLlmService（`integrations/mock/llm.py`）逐段

> 假 LLM——不调 API，返回预设内容。用于测试/开发（不花钱、不联网）。展示"最小实现"。

```python
class MockLlmService(LlmService):
    """Mock LLM——返回预设内容，测试用"""

    def __init__(self, response_content="Hello! This is a mock response."):
        self.response_content = response_content
        self.call_count = 0       # 记录调用次数（测试断言用）

    async def send_request(self, request) -> LlmResponse:
        """非流式：模拟延迟 + 返回预设内容"""
        self.call_count += 1
        await asyncio.sleep(0.1)   # 模拟处理延迟
        return LlmResponse(
            content=f"{self.response_content} (Request #{self.call_count})",
            finish_reason="stop",
            usage={"prompt_tokens": 50, "completion_tokens": 20, "total_tokens": 70},
        )

    async def stream_request(self, request):
        """流式：逐词 yield（模拟打字机）"""
        self.call_count += 1
        words = f"{self.response_content} (Streamed #{self.call_count})".split()
        for i, word in enumerate(words):
            await asyncio.sleep(0.05)   # 每词延迟
            yield LlmStreamChunk(
                content=word + (" " if i < len(words) - 1 else ""),
                finish_reason="stop" if i == len(words) - 1 else None,
            )

    async def validate_tools(self, tools):
        return []   # Mock 不做校验

    # 测试辅助方法
    def set_response(self, content): self.response_content = content
    def reset_call_count(self): self.call_count = 0
```

**关键**：Mock 也实现同一接口 → 测试时用 Mock（不用真调 API），`call_count` 能断言"调了几次"。

## 七、三个实现对比

| | SqliteRunner | MockLlmService | OpenAILlmService |
|---|---|---|---|
| 实现接口 | SqlRunner | LlmService | LlmService |
| 用途 | SQLite 数据库 | 测试/开发 | 生产 OpenAI |
| 核心逻辑 | 连库+执行+转DataFrame | 返回预设内容 | 打包payload+调API |
| 依赖 | sqlite3/pandas | 无 | openai 包 |
| 行数 | 65 | 65 | 267 |

**共同点**：都是"实现接口的类"——接口定义了"长什么样"，实现决定"连什么/调什么"。

## 八、可插拔的本质（核心认知）

```
Agent（只认接口）
  │
  ├─ llm_service: LlmService ← 可以是 Mock/OpenAI/Ollama
  │
  └─ tool_registry: ToolRegistry
       └─ RunSqlTool(sql_runner: SqlRunner) ← 可以是 SQLite/Postgres/ClickHouse
```

**换实现 = 换注入，不改 Agent 代码**：
```python
# 同一个 Agent，不同环境注入不同实现
if os.environ["ENV"] == "test":
    agent = Agent(llm_service=MockLlmService(), tool_registry=registry)
elif os.environ["ENV"] == "prod":
    agent = Agent(llm_service=OpenAILlmService(), tool_registry=registry)
```

**这就是依赖注入 + 面向接口编程**——接口是插座，实现是插头，Agent 是电器（只认插座）。

## 九、对照 ai_assistant 的改造动作

你的 `ai_assistant` 现在硬编码 MockLLM + SQLite。可插拔改造：

```python
# 现在（硬编码）
llm = MockLLM()                  # 写死 Mock
warehouse = MockWarehouse()      # 写死 SQLite
pipeline = QAPipeline(llm=llm, catalog=catalog)

# 改造：接口化
# ① 定义 SqlRunner 接口
class SqlRunner(ABC):
    async def run_sql(self, args) -> pd.DataFrame: ...

# ② 实现 SQLiteRunner（现在）+ 以后加 ClickHouseRunner
class SQLiteRunner(SqlRunner):
    async def run_sql(self, args):
        conn = sqlite3.connect(self.db_path)
        return pd.read_sql(args.sql, conn)

# ③ 注入：换环境只换实现
runner = SQLiteRunner("data.db")   # 或 ClickHouseRunner(...)
executor = QueryExecutor(runner)   # 执行器只认 SqlRunner 接口
```

**改造要点**：
1. 你的 `query_executor` 不直接连库 → 依赖 `SqlRunner` 接口
2. `llm_client` 已有接口（雏形）→ 加流式（阶段3已验证需要）
3. 换库/换模型只换注入，核心代码不改
