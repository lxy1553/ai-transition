## 一、为什么会走这条路？（先讲背景）

按学习计划阶段 1，本来是"跑通 `examples/mock_sqlite_example.py`"。
但我一跑就发现：**这个仓库的 examples/ 全部基于过时 API，当前代码跑不起来。**

### 实际遇到的 3 个 bug（逐个记录）

**Bug 1：import 路径错了**
```python
# examples/mock_sqlite_example.py 里写的：
from vanna.core.interfaces import LlmService   # ❌ 这个模块是空的

# 实际 LlmService 在：
from vanna import LlmService                    # ✅ vanna 顶层导出
```

**Bug 2：Agent 构造参数不够**
```python
# examples 只传了 2 个参数：
Agent(llm_service=llm, tool_registry=tools)

# 实际 Agent.__init__ 要求 4 个必填：
Agent(
    llm_service=llm_service,
    tool_registry=tool_registry,
    user_resolver=user_resolver,   # ★ 必填
    agent_memory=agent_memory,     # ★ 必填
)
```

**Bug 3：send_message 签名变了**
```python
# examples 传 user=user：
agent.send_message(user=user, message="...")

# 实际传 request_context：
agent.send_message(request_context=RequestContext(...), message="...")
```

### 关键决策：不修示例，改用真实 API 自己组装

> **教训**：开源项目主分支在快速演进，examples/ 往往过时。学的时候**以源码为准，别迷信示例**。
> 与其陷入"无穷适配旧示例"，不如读源码确认真实 API，自己组装——这本身才是真学会。

## 二、脚本 1：`01_最小可运行Agent.py`（最小 Agent）

### 目标
组装一个能跑的 Agent，验证"Agent 能组装起来、能回答"。

### 逐步拆解（每一段为什么这么写）

**① 让 python 找到 vanna**
```python
SRC = os.path.join(os.path.dirname(__file__), "..", "..", "vanna", "src")
sys.path.insert(0, os.path.abspath(SRC))
```
vanna 包在项目的 `src/` 下（src-layout），所以要把它加进 import 路径。
不 `pip install -e` 也能用（我的 pip 太旧，editable 安装失败了）。

**② 导入真实 API**
```python
from vanna import Agent, AgentConfig, User, ToolRegistry
from vanna.core.user.request_context import RequestContext
from vanna.core.user.resolver import UserResolver
from vanna.integrations.local.agent_memory.in_memory import DemoAgentMemory
from vanna.integrations.mock.llm import MockLlmService
from vanna.integrations.sqlite.sql_runner import SqliteRunner
from vanna.tools.run_sql import RunSqlTool
```
注意：`RequestContext` 不在 vanna 顶层，在 `vanna.core.user` 下——这就是读源码确认路径的重要性。

**③ 写一个最简单的 UserResolver**
```python
class StaticUserResolver(UserResolver):
    def __init__(self, user: User):
        self._user = user

    async def resolve_user(self, request_context: RequestContext) -> User:
        return self._user   # 不管请求里是啥，都返回这个测试用户
```
Agent 必填 `user_resolver`，所以得自己实现。生产环境会从 Cookie/JWT 里解析真实用户，
这里偷懒固定返回测试用户。

**④ 组装 Agent**
```python
agent = Agent(
    llm_service=MockLlmService(response_content="你好！..."),  # LLM：Mock，不花钱
    tool_registry=tool_registry,       # 工具：注册了 run_sql
    user_resolver=user_resolver,       # 用户解析
    agent_memory=DemoAgentMemory(),    # 记忆：零依赖内存版
    config=AgentConfig(stream_responses=False),  # 关流式，方便看输出
)
```

**⑤ 发送消息（用 RequestContext，不是 user=）**
```python
request_ctx = RequestContext(headers={"Authorization": "Bearer test-token"})
async for component in agent.send_message(
    request_context=request_ctx,
    message="你好",
    conversation_id="conv-001",
):
    # 从组件里取文本
    if component.rich_component and hasattr(component.rich_component, "content"):
        print(component.rich_component.content)
```

### 运行结果
```
👤 用户：你好
🤖 Agent：你好！我是用 Vanna 2.0 组装的最小 Agent。 (Request #1)
✅ 阶段1 最小 Agent 跑通！
```

### 这个脚本验证了什么
- Agent 能组装起来（4 个必填参数给全）
- send_message 用 RequestContext 能收到回答
- Mock LLM 能工作（不需要真 API Key）

**但还没验证核心**——工具调用循环。所以有脚本 2。

## 三、脚本 2：`02_触发工具调用.py`（工具调用循环，灵魂）

### 目标
触发**真实的工具调用循环**，亲眼看到：
```
LLM 返回 ToolCall（说"我要调 run_sql"）→ Agent 执行 SQL → 结果回喂 → LLM 基于结果回答
```

### 核心：写一个"会调用工具"的假 LLM

```python
class ToolCallingLlm(LlmService):
    def __init__(self):
        self.request_count = 0   # 记录这是第几次收到请求

    async def send_request(self, request: LlmRequest) -> LlmResponse:
        self.request_count += 1

        if self.request_count == 1:
            # 第一次：LLM 决定要查数据库 → 返回"工具调用"
            return LlmResponse(
                content="让我查一下数据库里的客户数量...",
                tool_calls=[
                    ToolCall(
                        id="call_001",
                        name="run_sql",   # 要调的工具名
                        arguments={"sql": "SELECT COUNT(*) AS total FROM Customer"},  # 参数
                    )
                ],
                finish_reason="tool_calls",   # 关键：标记"我还要继续，不是答完了"
            )
        else:
            # 第二次：LLM 看到了工具结果 → 生成最终回答
            tool_result = ""
            for msg in request.messages:      # 从请求历史里找工具结果
                if msg.role == "tool":
                    tool_result = msg.content
            return LlmResponse(
                content=f"查到了！数据库里共有 {tool_result} 个客户。",
                finish_reason="stop",         # 关键：标记"答完了"
            )
```

**这是真实 LLM 的简化版**：真实 LLM（DeepSeek/GPT）靠 prompt + function calling 决定何时返回
`tool_calls`，这里用"第几次请求"来模拟同样的行为。但**循环机制完全一样**——Agent 的
while 循环识别 `finish_reason == "tool_calls"`，就知道"还要继续"。

### 运行结果
```
👤 用户：数据库里有多少客户？
==================================================
🤖 让我查一下数据库里的客户数量...      ← 第一次：LLM 返回 ToolCall
🤖 Tool completed successfully        ← Agent 执行了 run_sql（真查了 SQLite）
🤖 查到了！数据库里共有 59 个客户。      ← 第二次：LLM 看到结果后回答
✅ 工具调用循环跑通
```

## 四、工具调用循环的数据流转（画图 + 每一步）

```
👤 用户："数据库里有多少客户？"
  │
  ▼
① send_message(request_context, message)
  │   agent.py:142
  ▼
② user_resolver.resolve_user() → 得到 User（含权限组）
  │
  ▼
③ 构建 system_prompt（把所有工具 schema 塞进去）
  │   agent.py:599  build_system_prompt(user, tool_schemas)
  │   → 工具 run_sql 的 schema 变成了 prompt 里的一段描述
  ▼
④ while 循环开始（agent.py:646）
  │
  ├── 第一次迭代：
  │     ⑤ llm.send_request(request)
  │        → ToolCallingLlm 第一次 → 返回 tool_calls=[run_sql]
  │     ⑥ response.is_tool_call() == True
  │        → 把 assistant 消息（含 tool_calls）加进会话历史（agent.py:663）
  │        → 遍历 tool_call：
  │            tool = registry.get_tool("run_sql")        ← 找到工具
  │            result = registry.execute(tool_call, ctx)   ← 执行 SQL！真查了 SQLite
  │        → 把结果作为 role="tool" 消息加进会话（agent.py:982）
  │        → 重新构建 request（带着工具结果）→ 回到 while 顶部
  │
  └── 第二次迭代：
        ⑤ llm.send_request(request)  ← 这次请求里带了工具结果
        → ToolCallingLlm 第二次 → 返回 content（最终回答）, finish_reason="stop"
        ⑥ is_tool_call() == False
        → yield response.content（回答给用户）→ break 退出循环
```

### 三个关键字段（读懂循环的钥匙）

| 字段 | 作用 | 出现在哪 |
|------|------|---------|
| `tool_calls` | LLM 说"我要调工具" | `response.tool_calls` |
| `finish_reason="tool_calls"` | LLM 说"我还没答完，要继续调工具" | `response.finish_reason` |
| `finish_reason="stop"` | LLM 说"我答完了" | `response.finish_reason` |

**Agent 的 while 循环就是靠 `finish_reason` 判断该退出还是继续**（`agent.py:658`）。

## 五、这一步学到了什么

### 硬能力
1. **Agent 的组装**：`Agent(llm, tool_registry, user_resolver, agent_memory)` 4 个必填
2. **工具注册**：`ToolRegistry.register_local_tool(tool, access_groups=[])`
3. **LLM 返回 ToolCall** 的结构：`{name, arguments, id}`
4. **while 循环**如何靠 `finish_reason` 判断继续/退出
5. **读源码**：import 报错时不猜，`grep -rn "class LlmService"` 找真实位置

### 软能力（更值钱）
1. **开源项目 examples 会过时**——以源码为准，别迷信示例
2. **不陷入"适配旧示例"**——确认真实 API 后自己组装，才是真学会
3. **"最小可运行"是学习工具**——先跑通最小闭环，再逐步加复杂度

### 对照自己的 ai_assistant
| Vanna | 我的项目 | 差距 |
|-------|---------|------|
| while 循环 + ToolCall | 8 步 if-else 固定顺序 | ❌ 差"LLM 决定下一步" |
| ToolRegistry 多工具 | 写死 1 个 sql 工具 | ❌ 差工具注册表 |
| finish_reason 控制循环 | 无此概念 | ❌ 差循环控制 |
