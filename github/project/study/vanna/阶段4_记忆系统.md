## 一、记忆的两类实现对比（阶段4 重点）

| | DemoAgentMemory（主干⑦ 已学）| ChromaAgentMemory（本阶段）|
|---|---|---|
| 存储 | 内存 list | ChromaDB 向量库 |
| 相似度 | Jaccard + difflib | **Embedding 向量** |
| 规模 | 小（内存）| 大（持久化）|
| 语义 | 字面相似 | **语义相似**（"坏账率"≈"逾期率"）|
| 适合 | 测试/开发 | 生产 |

**核心升级**：Demo 用"词重叠"算相似（字面），生产用"向量"算相似（语义）——"坏账率"和"逾期率"向量很近，能匹配上，Demo 匹配不上。

## 二、接口回顾（`capabilities/agent_memory/base.py`）

```python
class AgentMemory(ABC):
    # 存：记录一次成功的工具用法
    async save_tool_usage(question, tool_name, args, context, success=True): ...
    # 存：文本记忆
    async save_text_memory(content, context) -> TextMemory: ...
    # 查：找类似的工具用法（相似度检索）
    async search_similar_usage(question, context, *, limit=10, similarity_threshold=0.7): ...
    # 查：文本记忆
    async search_text_memories(query, context, *, limit=10, similarity_threshold=0.7): ...
    # 其他：最近记忆 / 删除 / 清空
    async get_recent_memories(context, limit=10): ...
    async delete_by_id(context, memory_id) -> bool: ...
    async clear_memories(context, tool_name=None): ...
```

**大白话**：接口 = "能存、能查、能删"。Demo 和 Chroma 都实现这套，只是"存哪、怎么查相似"不同。

## 三、ChromaAgentMemory 生产实现（`integrations/chromadb/agent_memory.py`）逐段

> 看生产级记忆：用 ChromaDB（向量数据库）存 + Embedding（向量）查。

### 构造（连接向量库 + 嵌入模型）

```python
class ChromaAgentMemory(AgentMemory):
    def __init__(self, collection_name="agent_memory",
                 persist_directory=None, embedding_function=None, distance_func="cosine"):
        # ① Embedding 函数（把文本变向量）
        #    没传就用 ChromaDB 默认（下载 ONNX 模型 ~80MB）
        self.embedding_function = embedding_function or \
            chromadb.utils.embedding_functions.DefaultEmbeddingFunction()

        # ② 创建 ChromaDB 客户端 + 集合
        self.client = chromadb.PersistentClient(path=persist_directory)  # 持久化到磁盘
        self.collection = self.client.get_or_create_collection(
            name=collection_name,
            embedding_function=self.embedding_function,
            metadata={"hnsw:space": distance_func},   # 距离算法：cosine
        )
```

**大白话**：
- `embedding_function` = 把文字变向量的"翻译器"（如 BGE 模型）
- `PersistentClient` = 存磁盘，重启不丢（vs Demo 内存重启就没了）
- `collection` = 存记忆的"表"（含向量）

### 存：save_tool_usage（向量库写入）

```python
async def save_tool_usage(self, question, tool_name, args, context, success=True, metadata=None):
    # ① 生成记忆 ID
    memory_id = str(uuid.uuid4())

    # ② 把内容转成向量（embedding 在 collection.add 内部自动做）
    self.collection.add(
        ids=[memory_id],
        documents=[question],            # ★ 存原问题（供检索）
        metadatas=[{
            "question": question,
            "tool_name": tool_name,
            "args": json.dumps(args),     # 参数序列化
            "success": success,
            "timestamp": self._now_iso(),
            **(metadata or {}),
        }],
    )
```

**大白话**：`collection.add(ids, documents, metadatas)`——一条记忆 = ID + 原问题（变向量）+ 附加信息（工具/参数/是否成功）。

### 查：search_similar_usage（向量检索）

```python
async def search_similar_usage(self, question, context, *, limit=10,
                               similarity_threshold=0.7, tool_name_filter=None):
    # ① 准备过滤条件（只搜成功的 + 按工具过滤）
    where = {"success": True}
    if tool_name_filter:
        where["tool_name"] = tool_name_filter

    # ② ★ 向量检索：把当前问题变向量，找最近的记忆
    results = self.collection.query(
        query_texts=[question],     # 当前问题（自动变向量）
        n_results=limit * 2,        # 多取一些再过滤
        where=where,                # 过滤条件
    )

    # ③ 计算相似度分数（距离 → 分数）
    #    ChromaDB 返回距离，转为相似度：1 - distance（cosine）
    for i in range(len(ids)):
        distance = distances[i]
        similarity = 1 - distance    # cosine 距离 → 相似度
        if similarity >= similarity_threshold:
            # 返回命中结果（问题 + 工具 + 参数）
            results.append(ToolMemorySearchResult(
                memory_id=ids[i],
                question=metadatas[i]["question"],
                tool_name=metadatas[i]["tool_name"],
                args=json.loads(metadatas[i]["args"]),
                similarity=similarity,
            ))
```

**大白话**：
- `collection.query(query_texts=[question])` = 把当前问题变向量，在向量库里找"最近的"（语义最像的）
- `similarity = 1 - distance` = 距离转相似度（cosine）
- 命中（≥0.7）→ 返回"之前成功的 SQL 模式"

## 四、Demo vs Chroma 的核心区别（一图）

```
用户问"上个月坏账率"
  │
  ├─ DemoAgentMemory（字面）：
  │    "坏账率" vs 记忆里的"逾期率" → 词不重叠 → 匹配不上 ❌
  │
  └─ ChromaAgentMemory（语义）：
       "坏账率" 和 "逾期率" → 向量很近 → 匹配上 ✅
       返回之前"逾期率"的成功 SQL → 复用
```

**大白话**：Demo 认字面（"坏账率"≠"逾期率"），生产认语义（"坏账率"≈"逾期率"）。这就是向量库的价值。

## 五、记忆在完整流程（训练式 RAG 运作）

```
用户问"上个月逾期率"
  → LLM 先调 search_saved_correct_tool_uses("上个月逾期率")
      → Chroma 向量检索 → 命中之前成功模式 → 返回 SQL
  → LLM 复用 SQL → 调 run_sql 执行
  → 成功 → LLM 调 save_question_tool_args(question, "run_sql", {sql})
      → Chroma 存入向量库（下次还能用）
  → 越用越聪明（记忆累积 + 语义检索）
```

## 六、对照 ai_assistant 的改造动作

你的 RAG 是"静态检索文档"。改造加记忆：

```python
# 现在：静态 RAG（每次现查指标文档）
def _handle_definition_query(self, query):
    docs = retriever.search(query)
    return explain(docs)

# 改造：加成功查询记忆（先 Demo 再 Chroma）
class CreditAgentMemory:
    def save_usage(self, question, sql, success):
        self._memories.append({question, sql, success})

    def search_usage(self, question):
        similar = [m for m in self._memories if similarity(question, m.question) > 0.7]
        return similar

# pipeline 里：查数前先搜记忆，命中复用
cached_sql = memory.search_usage(query)
if cached_sql:
    result = executor.execute(cached_sql)   # 复用
else:
    sql = sql_generator.generate(...)
    result = executor.execute(sql)
    if result.success:
        memory.save_usage(query, sql)       # 记住
```

**改造路径**：
1. 先加 `CreditAgentMemory`（内存，Demo 版）
2. 数据量大了 → 换 ChromaDB（向量版）
3. pipeline 查数前先搜记忆，成功后存记忆

## 七、小结

| 学到 | 一句话 |
|------|--------|
| 记忆接口 | 存（save_tool_usage）+ 查（search_similar_usage）|
| Demo 实现 | 内存 + Jaccard 字面相似（测试）|
| Chroma 实现 | 向量库 + Embedding 语义相似（生产）|
| 存 | collection.add（ID + 问题 + 元数据）|
| 查 | collection.query（向量检索 + 距离转分数）|
| 训练式 RAG | 先查记忆 → 复用 → 成功后存 → 越用越聪明 |

> **核心心法**：记忆 = 训练式 RAG。Demo 用字面相似，生产用语义相似（向量）。你的 RAG 加记忆后，从"静态检索"变"动态学习"。
