# ① Agent 循环 —— agent.py 646-1040 行

## 三问

**Q1 它解决什么问题？**
回答一个问题："用户问一句话，系统怎么决定下一步"。
不是一个固定流程，而是**让 LLM 在循环里自主决定**：要不要调工具、调哪个、看完结果下一步怎么办。

**Q2 它在数据流哪一环？**
核心中的核心。用户提问后，整个"理解→执行→回答"都发生在这个循环里：
```
用户 → [while循环] → LLM返回ToolCall → 执行工具 → 结果回喂 → 再问LLM → 回答
```

**Q3 如果删掉它会怎样？**
系统退化成"脚本"——没有自主性，只能走你写死的路径。这正是你 `ai_assistant` 现在的样子。

## 源码拆解（关键片段 + 注释）

文件位置：`src/vanna/core/agent/agent.py:646-1040`

### 循环入口
```python

while tool_iterations < self.config.max_tool_iterations:   # ① 最多循环 N 次（防死循环）
    # 发 LLM 请求

        response = await self._handle_streaming_response(request)   # 流式
    else:
        response = await self._send_llm_request(request)            # 非流式

    # 判断 LLM 想干什么
    if response.is_tool_call():        # ② LLM 说"我要调工具"
        tool_iterations += 1
        ...
    else:                              # ③ LLM 说"我答完了"
        yield response.content
        break
```

### LLM 返回 ToolCall 时（核心动作）
```python
if response.is_tool_call():
    # (a) 把 LLM 的 tool_calls 加进会话历史（OpenAI API 要求）
    assistant_message = Message(role="assistant", content=response.content, tool_calls=response.tool_calls)
    conversation.add_message(assistant_message)

    # (b) 逐个执行工具调用
    tool_results = []
    for i, tool_call in enumerate(response.tool_calls or []):
        tool = await self.tool_registry.get_tool(tool_call.name)     # 找到工具
        result = await self.tool_registry.execute(tool_call, context)  # 执行！(agent.py:827)
        tool_results.append({"tool_call_id": tool_call.id, "content": result.result_for_llm})

    # (c) 把工具结果作为 role="tool" 消息加进会话（agent.py:982-993）
    for tool_result in tool_results:
        conversation.add_message(Message(role="tool", content=tool_result["content"], tool_call_id=tool_result["tool_call_id"]))

    # (d) 重新构建 request（带着工具结果）→ 回到 while 顶部
    request = await self._build_llm_request(conversation, tool_schemas, user, system_prompt)
```

```python
else:  # LLM 没返回工具调用 = 答完了
    yield response.content
    break

# while 结束后检查是否撞上迭代上限
if tool_iterations >= self.config.max_tool_iterations:
    # 警告：卡在工具循环里了（比如 LLM 一直要调工具）
    # 这是防死循环的安全网
```

## 关键字段（循环的开关）

| 字段 | 值 | 含义 |
|------|-----|------|
| `finish_reason` | `"tool_calls"` | LLM 还要继续调工具 → 不退出 |
| `finish_reason` | `"stop"` | LLM 答完了 → 退出 |
| `max_tool_iterations` | 默认值 | 最多循环次数（防死循环）|

把你的 `_handle_indicator_query` 的 8 步 if-else 改成 while 循环：

# ② Tool 抽象 —— core/tool/base.py（70 行）

## 三问

**Q1 它解决什么问题？**
把"一个能力"（查库、发邮件、画图）统一封装成一个标准接口，让 LLM 能理解、能调用。

**Q2 它在数据流哪一环？**
工具是 Agent 的"手和脚"。LLM 说"调 run_sql"，Agent 找到这个 Tool 执行。

**Q3 如果删掉它会怎样？**
没有统一抽象，每个能力都写死一套调用，LLM 无法动态选择工具 → 无法成为 Agent。

## 源码拆解（全文解读）

文件位置：`src/vanna/core/tool/base.py`

```python
class Tool(ABC, Generic[T]):        # 所有工具必须继承
    @property
    @abstractmethod
    def name(self) -> str: ...       # 工具名（LLM 靠这个调用它）
                                    #   例：run_sql

    @property
    @abstractmethod
    def description(self) -> str: ...  # 描述（LLM 靠这个判断"何时用"）
                                    #   例："执行SQL查询，返回结果DataFrame"

    @property
    def access_groups(self) -> List[str]:  # 权限组（谁能用）
        return []                    # 空 = 所有人可用

    @abstractmethod
    def get_args_schema(self) -> Type[T]:  # 参数结构（Pydantic 模型）
        ...                          # LLM 靠这个填参数（JSON Schema）
                                    #   例：{"sql": str}

    @abstractmethod
    async def execute(self, context: ToolContext, args: T) -> ToolResult:
        ...                          # 真正干活的地方

    def get_schema(self) -> ToolSchema:   # 生成给 LLM 看的 schema
        args_model = self.get_args_schema()
        schema = args_model.model_json_schema()
        return ToolSchema(name=self.name, description=self.description, parameters=schema, ...)
```

## 关键洞察

**一个工具 = 名字 + 描述 + 参数schema + 执行函数 + 权限**。这就是 function calling 的本质——
LLM 看到 `get_schema()` 生成的 JSON Schema，就知道"这个工具干什么、参数怎么填"。

## 对照 ai_assistant 的改造动作

你的 `ai_assistant` 没有"工具"概念，SQL 生成写死。加一个 `RunSqlTool`：
```python
class RunSqlTool(Tool[SqlArgs]):
    name = "run_sql"
    description = "执行SQL查询信贷数仓，返回结果"
    access_groups = ["analyst"]          # 权限：只有分析师能用

    def get_args_schema(self):
        return SqlArgs                   # Pydantic: {"sql": str}

    async def execute(self, context, args):
        result = executor.execute(args.sql)   # 复用你的 QueryExecutor
        return ToolResult(success=True, result_for_llm=str(result.data))
```

# ③ Registry 分派 —— core/registry.py

## 三问

**Q1 它解决什么问题？**
管理所有工具：注册、按名字查找、统一执行（带权限/参数校验/审计）。

**Q2 它在数据流哪一环？**
Agent 循环里"执行工具"那一步：`tool_registry.get_tool(name)` → `tool_registry.execute(tool_call)`。

**Q3 如果删掉它会怎样？**
工具散落各处，LLM 的 tool_call.name 找不到对应执行者 → 循环断裂。

## 源码拆解

文件位置：`src/vanna/core/registry.py:46-278`

### 注册
```python
class ToolRegistry:
    def __init__(self):
        self._tools: Dict[str, Tool] = {}   # name → Tool

    def register_local_tool(self, tool, access_groups):
        # ★ 注意：方法是 register_local_tool，不是 register()！
        # 有 access_groups 就包一层 _LocalToolWrapper 做权限校验
        if access_groups:
            self._tools[tool.name] = _LocalToolWrapper(tool, access_groups)
        else:
            self._tools[tool.name] = tool
```

### execute() 的完整流水线（registry.py:144-278）——这是精华
```python
async def execute(self, tool_call, context):
    # 1. 找到工具
    tool = await self.get_tool(tool_call.name)
    if not tool:
        return ToolResult(success=False, error=f"Tool '{tool_call.name}' not found")

    # 2. 权限校验
    if not await self._validate_tool_permissions(tool, context.user):
        return ToolResult(success=False, error="Insufficient group access...")

    # 3. 参数校验（Pydantic）
    args_model = tool.get_args_schema()
    validated_args = args_model.model_validate(tool_call.arguments)

    # 4. 参数转换（★ 可做行级安全/敏感字段脱敏）
    transform_result = await self.transform_args(tool=tool, args=validated_args, user=context.user, context=context)
    if isinstance(transform_result, ToolRejection):
        return ToolResult(success=False, error=transform_result.reason)

    # 5. 真正执行
    result = await tool.execute(context, final_args)

    # 6. 审计（谁在什么时间调了什么工具）
    await self.audit_logger.log_tool_invocation(...)
    return result
```

## 关键洞察

**execute() = 权限 + 参数校验 + 参数转换 + 执行 + 审计**，每一步都是安全关卡。
`transform_args()` 是扩展点——可以做行级安全（不同用户查数自动加 WHERE user_id=...）。

## 对照 ai_assistant 的改造动作

你的权限在 pipeline 判一次，Vanna 是**每个工具调用都判**。把你的权限检查移到工具执行层：
```python
# 现在：pipeline 判一次
if not self.permission.check(indicator_name, user_role): return 拒绝

# 改造：交给 ToolRegistry.execute() 自动判（工具带 access_groups）
# 不同用户查同一指标，transform_args 自动加行级过滤
```

# ④ LlmService 抽象 —— core/llm/base.py（40 行）

## 三问

**Q1 它解决什么问题？**
统一所有 LLM 的接口，让 Agent 不关心底层是 OpenAI 还是 Ollama。

**Q2 它在数据流哪一环？**
Agent 循环里"发 LLM 请求"那一步：`llm_service.send_request(request)`。

**Q3 如果删掉它会怎样？**
每种 LLM 一套调用方式，换模型要改 Agent 代码 → 耦合。

## 源码拆解（全文）

文件位置：`src/vanna/core/llm/base.py`

```python
class LlmService(ABC):
    @abstractmethod
    async def send_request(self, request: LlmRequest) -> LlmResponse:
        """非流式：发请求，拿完整回答"""
        pass

    @abstractmethod
    async def stream_request(self, request: LlmRequest):
        """流式：边生成边返回 chunk（LLM 打字机效果）"""
        raise NotImplementedError
        yield  # 关键：这是 async generator，必须有 yield

    @abstractmethod
    async def validate_tools(self, tools: List[Any]) -> List[str]:
        """验证工具 schema，返回错误列表"""
        pass
```

## 关键洞察

- 三个方法：`send_request`（非流式）、`stream_request`（流式）、`validate_tools`（工具校验）
- **你的 `LLMClient` 接口（chat/chat_json）就是它的雏形**，但它多了流式 + 工具校验
- 生产实现都在 `integrations/`：openai/ollama/anthropic/deepseek 各一个文件，都实现这个接口 → 可插拔

## 对照 ai_assistant 的改造动作

你的 `LLMClient` 已有 chat/chat_json。加流式支持：
```python
# 现在：LLMClient.chat() 一次返回完整文本
# 改造：加 stream_chat()，边生成边 yield（对接 SSE 前端）
```

# ⑤ models —— core/tool/models.py（ToolCall/ToolResult/ToolContext）

## 三问

**Q1 它解决什么问题？**

**Q2 它在数据流哪一环？**

**Q3 如果删掉它会怎样？**

## 源码拆解（四个核心模型）

文件位置：`src/vanna/core/tool/models.py`

### ToolCall —— LLM 说"我要调这个工具"
```python
class ToolCall(BaseModel):

    name: str                     # 工具名（registry 靠它找工具）
    arguments: Dict[str, Any]     # 参数（LLM 填的原始 JSON）
```

### ToolContext —— 每次工具调用都带着上下文（★ 关键）
```python
class ToolContext(BaseModel):
```

# ⑥ 用户/权限 —— core/user/（User + UserResolver + RequestContext）

## 三问

**Q1 它解决什么问题？**

**Q2 它在数据流哪一环？**

# ⑦ 记忆 —— capabilities/agent_memory/ + tools/agent_memory.py

## 三问

**Q1 它解决什么问题？**
记住"哪些查询模式成功过"，下次类似问题复用，避免重复犯同样错误。

**Q2 它在数据流哪一环？**
作为 ToolContext 的一部分，**每个工具调用都带着记忆**——工具执行后可以"记住"这次用法。

**Q3 如果删掉它会怎样？**
每次都是冷启动，同样的错反复犯 → 效果上不去。

## 源码拆解

### 记忆接口（`capabilities/agent_memory/base.py`）
```python
class AgentMemory(ABC):
    # 存：记录一次成功的工具用法
    async def save_tool_usage(self, question, tool_name, args, context, success=True): ...

    # 查：找类似的历史成功用法（相似度检索）
    async def search_similar_usage(self, question, context, limit=10, similarity_threshold=0.7): ...
```

### 记忆工具（`tools/agent_memory.py`）
两个工具，注册进 ToolRegistry，LLM 可以主动调用：
```python
class SaveQuestionToolArgsTool(Tool[...]):   # 工具名：save_question_tool_args
    # "记住：这个问题用这个工具和参数成功了"
    # → 调 agent_memory.save_tool_usage

class SearchSavedCorrectToolUsesTool(Tool[...]):   # 工具名：search_saved_correct_tool_uses
    # "找类似问题之前怎么成功的"
    # → 调 agent_memory.search_similar_usage
```

### 内存实现（`integrations/local/agent_memory/in_memory.py`）
`DemoAgentMemory`：零依赖，用 Jaccard/difflib 做相似度（不用向量库）。我们阶段 1 用的就是它。

## 关键洞察

**这是"训练式 RAG"**：不是每次现查，而是**记住成功的 query→SQL 映射**。
用户下次问类似问题，先搜记忆，命中就直接复用之前的 SQL 模式。

## 对照 ai_assistant 的改造动作

你的 RAG 是"静态检索文档"，Vanna 是"动态学习成功模式"。改造：
```python

# 改造：加"成功查询记忆"——用户问过且查对的 SQL 存下来，下次类似问题优先复用
```

# 七、总结：七个主干的关系图

```
                    UserResolver（⑥ 解析用户）
                          │
                          ▼
┌─────────────────────────────────────────────┐
│              Agent 循环（① 核心）              │
│  while ...:                                 │
│    llm.send_request()  ← LlmService（④）     │
│    if tool_call:                           │
│      registry.execute() ← Registry（③）      │
│        → Tool.execute() ← Tool 抽象（②）     │
│        → 全程带 ToolContext + 记忆（⑤⑦）      │
│    else:                                   │
│      yield answer                           │
└─────────────────────────────────────────────┘
```

**一句话**：User 知道谁在问，Agent 循环决定做什么，LLM 服务提供思考，Tool 提供能力，
Registry 安全地调度，Context 贯穿身份和记忆。
