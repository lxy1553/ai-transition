# Vanna 学习 04c：完整交互图（一个问题从进来到答案）

> 把主干① + 扩展点串成一条线：**用户问一句话，代码是怎么一步步流转的**。
> 所有行号都已用 `grep` 在 `agent.py` 里核实，不是猜的。
>
> 学习方式：先看完整图，再对照行号读代码。

---

## 一句话

```
用户提问 → 解析身份 → 拦截检查 → 进循环（LLM↔工具来回） → 兜底 → 回答
```

## 三个容易混淆的点（grill-me 修正记录）

### 1. empty / is_refusal 的位置
**误区**：以为"问题刚进来"先判断。
**真相**：它们是对 **LLM 响应** 的判断，必须**在循环内 `response = llm(...)` 之后**。
而且 Vanna 本身没有这两个方法——是生产级补全（见 04b）。

### 2. 4 个钩子的位置
**误区**：以为钩子都在循环外。
**真相**：
- before_message（373）→ **循环前**
- before_tool（787）、after_tool（848）→ **循环内**（每次工具执行）
- after_message（1119）→ **循环后**

### 3. LlmMiddleware 的位置
**误区**：以为它是"循环前一步"。
**真相**：它**在循环内部，每次迭代都跑**（1244 发前 / 1290 拿到后）。
不是"走完中间件再进循环"，而是"循环的每一步都套着中间件"。

## 一句话总结

**从问题进来到答案** = `解析身份 → 拦截检查 → 循环（LLM↔工具）→ 兜底 → 收尾`。
主干①（循环）是引擎，扩展点（①②③④⑥⑦）是引擎外的"壳"。
