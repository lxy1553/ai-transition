## 一、熔断 + 重试（resilience.py）

### 重试（指数退避）

```python
def retry_async(max_attempts=None):
    """异步重试装饰器（指数退避）"""
    return retry(
        stop=stop_after_attempt(max_attempts or settings.LLM_MAX_RETRIES),
        wait=wait_exponential(multiplier=0.5, min=0.5, max=8),   # 指数退避
        retry=retry_if_exception_type(Exception),
        reraise=True,
    )
```

**大白话**：LLM/embedding 调用失败自动重试，越等越久（0.5s→1s→...→8s），防外部抖动。

### 熔断器（防雪崩）

```python
class CircuitBreaker:
    """轻量熔断器：连续失败达阈值 → 短路 → 半开试探"""
    def __init__(self, name, fail_threshold=5, reset_timeout=30.0):
        self._failures = 0
        self._opened_at = None

    async def call(self, fn, *args, **kwargs):
        if not self._allow():                       # 熔断打开 → 直接拒绝
            raise CircuitOpenError(f"熔断器 {self.name} 处于打开状态")

        try:
            result = await fn(*args, **kwargs)
        except Exception:
            self._failures += 1
            if self._failures >= self.fail_threshold:
                self._opened_at = time.monotonic()  # ★ 打开熔断
            raise
        else:
            self._failures = 0                      # 成功重置
            self._opened_at = None
            return result
```

**大白话**：连续失败 5 次 → 熔断 30 秒（直接拒绝不调 LLM）→ 半开试探一次 → 成功关闭。**防 LLM 挂了拖垮所有请求**。

### 命名熔断器（按外部依赖各一个）

```python
_breakers = {}

def get_breaker(name):
    """获取/创建命名熔断器（llm / embedding / rerank 各一个）"""
    if name not in _breakers:
        _breakers[name] = CircuitBreaker(name, ...)
    return _breakers[name]
```

**大白话**：LLM、embedding、rerank 各一个熔断器——一个挂了不影响另一个。

### 并发闸（防打爆下游）

```python
_llm_sem = None
def llm_semaphore():
    """全局信号量，限制同时进行的 LLM 调用数"""
    global _llm_sem
    if _llm_sem is None:
        _llm_sem = asyncio.Semaphore(settings.LLM_MAX_CONCURRENCY)
    return _llm_sem
```

**大白话**：限制同时调 LLM 的数量（如 10 个），防多用户把 LLM API 打爆。

## 二、限流（limiter.py）

```python
def _rate_key(request):
    """限流维度：优先 user_id，兜底 IP"""
    user_id = getattr(request.state, "user_id", None)
    if user_id:
        return f"user:{user_id}"          # 已登录 → 按用户限流
    return get_remote_address(request)    # 未登录 → 按 IP

limiter = Limiter(
    key_func=_rate_key,
    default_limits=[settings.RATE_LIMIT_DEFAULT],   # 如 60 次/分钟
    storage_uri=settings.redis_url if settings.REDIS_ENABLED else "memory://",
    strategy="moving-window",                       # 滑动窗口
)
```

**大白话**：每用户 60 次/分钟。配 Redis = 分布式限流（多 Pod 共享）。**防免费用户刷爆 LLM**（成本控制）。

## 三、缓存（cache.py）

```python
def _normalize(text):
    """问题归一化：小写、去空白、去标点"""
    return re.sub(r"[\s，。？！、,.?!;:\"'`]+", "", text.lower().strip())

def cache_key(db_id, question):
    digest = hashlib.sha256(f"{db_id}::{_normalize(question)}".encode()).hexdigest()[:32]
    return f"qf:sql:{digest}"

async def get_cached(db_id, question):
    redis = await get_redis()
    if redis is None: return None                    # 未启用/失败 → 降级 miss
    raw = await redis.get(cache_key(db_id, question))
    return json.loads(raw) if raw else None

async def set_cached(db_id, question, payload):
    await redis.set(cache_key(db_id, question), json.dumps(payload), ex=settings.CACHE_TTL_SECONDS)
```

**大白话**：归一化问题 → 哈希键 → Redis 缓存。**相同 query 命中直接返回，不调 LLM**（省钱核心）。

## 四、优雅降级（贯穿全局约定）

```python
# 所有外部依赖（Redis/Langfuse/rerank/ES/语义缓存）未配置或出错时
# 一律降级为 no-op 或回退，不阻断主链路
```

**大白话**：缓存挂了？当没缓存（miss）。rerank 挂了？直接用 RRF 结果。**任何可选组件挂了都不影响主链路**——可用性 > 完美。

## 五、对照 ai_assistant 的改造动作

```python
# ① 熔断：给 llm_client 包 CircuitBreaker
breaker = CircuitBreaker("llm", fail_threshold=5, reset_timeout=30)
async def llm_call(prompt):
    return await breaker.call(llm.chat, prompt)   # LLM 挂了快速失败

# ② 重试：LLM 调用加指数退避
@retry_async(max_attempts=3)
async def llm_call(prompt):
    return await llm.chat(prompt)

# ③ 缓存：相同 query 不重复烧 LLM
async def ask(query, user_role):
    cached = await redis.get(normalize(query))
    if cached: return cached
    answer = pipeline.ask(query, user_role)
    if answer.success: await redis.set(normalize(query), answer, ex=3600)
    return answer

# ④ 限流：每用户 60 次/分钟
@limiter.limit("60/minute")
async def ask(query, user_role): ...
```

**改造要点**：熔断 + 重试 + 缓存 + 限流——四个都是生产级关键，你 ai_assistant 全缺。

## 六、小结

| 学到 | 一句话 |
|------|--------|
| 熔断 | 连续失败短路，防雪崩 |
| 重试 | 指数退避，防抖动 |
| 并发闸 | 限 LLM 并发，防打爆 |
| 限流 | 按用户限流，防刷 |
| 缓存 | 相同 query 不重复烧 LLM |
| 优雅降级 | 可选组件挂了不影响主链路 |

> **核心心法**：生产韧性 = 熔断 + 重试 + 并发闸 + 限流 + 缓存 + 优雅降级。你 ai_assistant 最该先加 **熔断 + 缓存**（防 LLM 挂了拖垮 + 相同问题省钱）。
