# 深挖：OCR 识别器内部（deepdoc/vision/ocr.py）

> RAGFlow 的 OCR 是 **DB 检测器（det）+ CTC 识别器（rec）两段式**，外加「透视摆正 + 三方向择优」处理倾斜文字。
> 本文件拆 `load_model` → `TextDetector` → `TextRecognizer` → `OCR.__call__` 完整管线，以及它和 PaddleOCR 的关系。

- 源码位置：`github/project/ragflow/deepdoc/vision/ocr.py`（703 行）+ 基类 `recognizer.py` + 算子 `operators.py` + 后处理 `postprocess.py`
- 上游：深挖 03_01 的 `RAGFlowPdfParser.__ocr`（pdf_parser.py:771）逐页调 OCR；布局识别复用同一个 `load_model`

## 一、`load_model` —— ONNX 会话 + CUDA/CPU + 模块级缓存（ocr.py:70）

```python
loaded_models = {}                                  # ocr.py:36  模块级缓存，跨实例复用同一 onnx 会话

def load_model(model_dir, nm, device_id: int | None = None):     # ocr.py:70
    model_file_path = os.path.join(model_dir, nm + ".onnx")      # 拼出 det.onnx / rec.onnx
    model_cached_tag = model_file_path + str(device_id) if device_id is not None else model_file_path
    loaded_model = loaded_models.get(model_cached_tag)           # ★ 以 "path+device_id" 为 key 查缓存
    if loaded_model:
        return loaded_model                                      # 命中直接复用（OCR 多个实例共享一个会话）

    def cuda_is_available():                                     # 用 torch.cuda 探测 CUDA 可用性
        pip_install_torch(); import torch
        return torch.cuda.is_available() and torch.cuda.device_count() > target_id

    options = ort.SessionOptions()                               # 显式线程数，避免多 worker 下 CPU 过订阅
    options.intra_op_num_threads = int(os.environ.get("OCR_INTRA_OP_NUM_THREADS", "2"))
    options.inter_op_num_threads = int(os.environ.get("OCR_INTER_OP_NUM_THREADS", "2"))

    if cuda_is_available():
        cuda_provider_options = {"device_id": provider_device_id,
                                 "gpu_mem_limit": gpu_mem_limit_mb * 1024 * 1024,
                                 "arena_extend_strategy": "kNextPowerOfTwo"}
        sess = ort.InferenceSession(model_file_path, options=options,
                                    providers=["CUDAExecutionProvider"], provider_options=[cuda_provider_options])
    else:
        sess = ort.InferenceSession(model_file_path, options=options, providers=["CPUExecutionProvider"])
    loaded_models[model_cached_tag] = (sess, run_options)        # 写回模块级缓存
    return sess, run_options
```

**作用（关键）**：**一个 onnx 会话全进程复用**——`det`/`rec`/`layout` 模型都走这个 `load_model`，key 是 `模型路径+device_id`。**多 worker 部署时显式设线程数**（2）防止 CPU 过订阅；CUDA 可用走 GPU provider，否则 CPU。

## 三、`detect` —— DB 文本检测（ocr.py:601 + TextDetector:379）

```python
def detect(self, img, device_id: int | None = None):    # ocr.py:601
    dt_boxes, _ = self.text_detector[device_id](img)    # ★ DB 检测器 → 文本框（四边形）
    if dt_boxes is None:
        return None
    return zip(self.sorted_boxes(dt_boxes),             # 排序后 (文本框, 空文本占位) 对
               [("", 0) for _ in range(len(dt_boxes))])
```

底层 `TextDetector.__call__`（ocr.py:455-482）——**检测后处理链**：

```python
# 预处理：DetResizeForTest（limit=960 最长边缩放）→ NormalizeImage → ToCHWImage → KeepKeys
# 推理：ort_session.run(det.onnx)
# 后处理：DBPostProcess → 二值化+膨胀找连通域 → 每个文本行一个四边形框 [N,4,2]
return dt_boxes, elapse     # dt_boxes 是 [N,4,2]：N 个文本行，每行 4 个角点
```

**作用**：**DB（Differentiable Binarization）检测器**找出"哪几块是文字"——输出不是矩形而是**四边形**（容忍倾斜）。`sorted_boxes` 把四边形按从上到下、从左到右排序（阅读序）。

## 四、`get_rotate_crop_image` —— 透视摆正 + 三方向择优（ocr.py:535）

```python
def get_rotate_crop_image(self, img, points):            # ocr.py:535  四点四边形
    # ① 上下边取长的做宽、左右边取长的做高 → 目标矩形尺寸
    img_crop_width  = int(max(np.linalg.norm(points[0]-points[1]), np.linalg.norm(points[2]-points[3])))
    img_crop_height = int(max(np.linalg.norm(points[0]-points[3]), np.linalg.norm(points[1]-points[2])))
    pts_std = np.float32([[0,0],[img_crop_width,0],[img_crop_width,img_crop_height],[0,img_crop_height]])
    # ② ★ 透视变换：任意倾斜四边形 → 水平矩形（摆正的关键）
    M = cv2.getPerspectiveTransform(points, pts_std)
    dst_img = cv2.warpPerspective(img, M, (img_crop_width, img_crop_height),
                                  borderMode=cv2.BORDER_REPLICATE, flags=cv2.INTER_CUBIC)
    # ③ ★ 竖长块（高/宽≥1.5）：可能方向错了，试 0°/90°/270° 用识别分数选最优
    if dst_img_height * 1.0 / dst_img_width >= 1.5:
        text, score = self.text_recognizer[0]([dst_img])[0][0]; best = (score, dst_img)
        rotated_cw = np.rot90(dst_img, k=3)              # 顺时针 90°
        text, score = self.text_recognizer[0]([rotated_cw])[0][0]
        if score > best_score: best = (score, rotated_cw)
        rotated_ccw = np.rot90(dst_img, k=1)             # 逆时针 90°
        ...
        dst_img = best_img                               # ★ 取识别分最高的方向
    return dst_img
```

**作用（关键）**：**倾斜文字的处理核心**——
1. **透视变换摆正**：检测到的是任意四边形的框，`getPerspectiveTransform` 求单应矩阵，`warpPerspective` 摆正成水平矩形再裁剪。
2. **三方向择优**：竖排/旋转的文本块（高/宽≥1.5）直接识别分数低，**把图转 90°/270° 各识别一次，取分数最高的方向**——用识别器自己的置信度当"方向投票器"，**不需要独立的方向分类模型**。

## 五、`TextRecognizer.__call__` —— 批量识别 + CTC 解码（ocr.py:329）

```python
def __call__(self, img_list):                            # ocr.py:329
    width_list = [img.shape[1]/float(img.shape[0]) for img in img_list]
    indices = np.argsort(np.array(width_list))           # ★ 按宽高比排序（同批图等宽 → 加速）
    batch_num = self.rec_batch_num                       # =16 一批
    for beg_img_no in range(0, img_num, batch_num):
        max_wh_ratio = imgW / imgH
        for ino in range(beg_img_no, end_img_no):
            max_wh_ratio = max(max_wh_ratio, wh_ratio)   # 该批最宽的图决定 pad 宽度
        for ino in range(beg_img_no, end_img_no):
            norm_img = self.resize_norm_img(img_list[indices[ino]], max_wh_ratio)  # 高 48、宽按比例 pad 到 320、归一化 [-1,1]
            norm_img_batch.append(norm_img[np.newaxis, :])
        preds = self.predictor.run(None, {self.input_tensor.name: np.concatenate(norm_img_batch)}, self.run_options)
        rec_result = self.postprocess_op(preds)          # ★ CTCLabelDecode → [文本, 分数]
        for rno in range(len(rec_result)):
            rec_res[indices[beg_img_no+rno]] = rec_result[rno]   # 还原到原顺序
    return rec_res, time.time() - st
```

**作用**：**识别器（CTC）批量推理**——按宽高比排序让同批图像宽度一致（省 pad），每批 16 张，`resize_norm_img` 缩放到高 48、宽按最宽图 pad，CTC 解码（`CTCLabelDecode`）输出 `[文本, 分数]`，最后还原回原始顺序。

## 六、`OCR.__call__` —— 完整管线唯一入口（ocr.py:660）

```python
def __call__(self, img, device_id=0, cls=True):          # ocr.py:660
    time_dict = {"det": 0, "rec": 0, "cls": 0, "all": 0}
    if img is None: return None, None, time_dict
    ori_im = img.copy()
    dt_boxes, elapse = self.text_detector[device_id](img)      # ① DB 检测文本行四边形
    time_dict["det"] = elapse
    if dt_boxes is None: return None, None, time_dict
    dt_boxes = self.sorted_boxes(dt_boxes)                     # ② 从上到下、从左到右排序
    img_crop_list = []
    for bno in range(len(dt_boxes)):                           # ③ 逐框透视摆正 + 裁剪
        img_crop = self.get_rotate_crop_image(ori_im, copy.deepcopy(dt_boxes[bno]))
        img_crop_list.append(img_crop)
    rec_res, elapse = self.text_recognizer[device_id](img_crop_list)   # ④ 批量识别
    time_dict["rec"] = elapse
    filter_boxes, filter_rec_res = [], []
    for box, rec_result in zip(dt_boxes, rec_res):             # ⑤ 按 drop_score=0.5 过滤低分
        text, score = rec_result
        if score >= self.drop_score:
            filter_boxes.append(box); filter_rec_res.append(rec_result)
    return list(zip([a.tolist() for a in filter_boxes], filter_rec_res))   # [(box_4x2, (text, score))]
```

**作用**：整条管线的串联——**检测 → 排序 → 摆正裁剪 → 批量识别 → 分数过滤**，返回 `[(文本行四边形, (文本, 分数))]`。PDF 解析器拿这个结果继续和 pdfplumber 抽的字符合并（深挖 03_01 的 `__ocr`）。

## 七、方向分类 cls —— RAGFlow 里没有

`__call__` 签名里的 `cls=True` 是 **PaddleOCR 遗留的接口参数**，函数体内从未被读取（`time_dict["cls"]` 恒为 0）。全 `deepdoc/vision/` 下无 `TextClassifier`/方向分类模型。

**方向校正的实际承担者**是 `get_rotate_crop_image` 里的「三方向旋转 + 识别分数择优」（第 4 点），不是独立 cls 模型。

**学习点**：读开源代码时，**`cls` 这类参数可能是从上游框架（PaddleOCR）拷来的残留**——签名在、实现没了。认出来比照抄更重要。

## 八、数据流转示意

```
页面图像 img
  │
  ▼
OCR.__call__ (ocr.py:660)
  │  ① TextDetector[device] (det.onnx, DB 检测器)
  │      预处理: DetResizeForTest(limit=960) → NormalizeImage → ToCHWImage
  │      推理 + DBPostProcess → dt_boxes: [N,4,2] 文本行四边形
  ▼
  │  ② sorted_boxes → 从上到下、从左到右
  ▼
  │  ③ get_rotate_crop_image 逐框 (ocr.py:535)
  │      透视变换摆正 (高/宽≥1.5 时 0°/90°/270° 识别分择优)
  ▼  img_crop_list: [N,48,320,3]
  │  ④ TextRecognizer[device] (rec.onnx, CTC)
  │      按宽高比排序 + 16 张/批 + resize_norm_img → CTCLabelDecode → [(text,score)]
  ▼
  │  ⑤ score ≥ 0.5 过滤
  ▼
[(box_4x2, (text, score))]  →  PDF 解析器合并字符 / 布局识别打标
```

## 九、对照 ai_assistant

| RAGFlow | 你的 ai_assistant | 差距 |
|---------|------------------|------|
| DB 检测 + CTC 识别两段式 OCR | 无 | ❌ 图片/扫描件读不了 |
| 透视摆正 + 三方向择优 | 无 | ⚠️ 倾斜/竖排文本会识别失败 |
| `drop_score=0.5` 分数过滤 | 无 | ⚠️ 低置信文本宁缺毋滥 |
| 多 GPU 按卡分派 | 无 | 概念参考 |
| 会话级模型缓存 + 显式线程数 | 无 | 生产部署要抄 |

**落地优先级**：
- **P0**：先接**现成 OCR 服务**（PaddleOCR / Tesseract / 云 OCR），不做两段式自研——验证"图片型 PDF 进知识库"的价值。
- **P1**：`drop_score` 置信度过滤——OCR 结果按分数过滤，宁缺毋滥，防止乱码污染知识库。
- **P2**：倾斜文本处理（透视摆正）——扫描件方向不正是高频坑。

## 十、总结

| 环节 | 代码 | 作用 |
|------|------|------|
| 模型加载 | `load_model`（70） | onnx 会话 + CUDA/CPU + 模块级缓存 |
| 初始化 | `OCR.__init__`（488） | 按 GPU 数建 detector+recognizer 列表 |
| 文本检测 | `detect` + `TextDetector`（601/379） | DB 检测器 → 文本行四边形 |
| 摆正裁剪 | `get_rotate_crop_image`（535） | 透视变换 + 三方向识别分择优 |
| 批量识别 | `TextRecognizer`（129/329） | 宽高比排序 + 16/批 + CTC 解码 |
| 完整管线 | `OCR.__call__`（660） | 检测→排序→摆正→识别→过滤 |
| 分数过滤 | `drop_score=0.5` | 低置信框丢弃 |

**一句话心法**：**OCR = 检测（"字在哪"）+ 识别（"字是啥"）两段式**，中间靠「透视摆正」解决倾斜、靠「识别分数择优」解决方向、靠「drop_score」解决置信度。RAGFlow 的 OCR 是 PaddleOCR 的裁剪版——去掉了方向分类器，用识别分数本身做方向投票，更省一个模型。
