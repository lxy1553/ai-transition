# RAGFlow 架构与数据流总览（按项目自身阶段）

> 本项目不照搬任何学习框架的阶段划分，而是**按 RAGFlow 自身的架构数据流**分阶段。
> 一句话：一条文档从「上传」到「被回答」，RAGFlow 走了 **离线链路（数据准备）+ 在线链路（知识应用）** 两条路，外加一套贯穿全程的支撑机制。
>
> 项目位置：`github/project/ragflow` ｜ 开始时间：2026-08-20

---

## 一、RAGFlow 自身的架构地图

```
┌─────────────────────── 离线链路（数据准备 · 异步 · 可重跑）───────────────────────┐
│                                                                                │
│  ① 数据接入与任务调度         ② 文档解析          ③ 分块           ④ 分词与向量化     ⑤ 索引写入   │
│  ┌──────────────┐        ┌─────────────┐    ┌───────────┐    ┌──────────────┐   ┌─────────┐  │
│  │ File 组件    │        │ Parser 组件  │    │ Chunker   │    │ Tokenizer    │   │ 文档库   │  │
│  │ 上传/存储/队列│──▶     │ DeepDoc 多引擎│──▶│ 模板化分块 │──▶│ 多路分词+embedding│──▶│ES/Infinity│ │
│  │ TaskExecutor │        │ 版面/OCR/表格 │    │           │    │              │   │ chunk+向量│  │
│  └──────────────┘        └─────────────┘    └───────────┘    └──────────────┘   └─────────┘  │
│   （01）                   （03）             （04）          （05）              （08）       │
└────────────────────────────────────────────────────────────────────────────────────────────┘
                                          │  产出一个「知识库」：chunk 文本 + 向量 + 关键词 + 元数据
                                          ▼
┌─────────────────────── 在线链路（知识应用 · 同步 · 低延迟）───────────────────────┐
│                                                                                │
│  ⑥ 混合检索           ⑦ 重排精排           ⑧ 在线问答与 RAG 组装                 │
│  ┌──────────────┐   ┌─────────────┐   ┌──────────────────────────────┐         │
│  │ Dealer.search │──▶│ Rerank 模型  │──▶│ 拼 context + LLM 生成 + 引用  │         │
│  │ 向量+BM25 fusion│   │ 归一化 [0,1] │   │ SSE 流式 + 前端高亮           │         │
│  └──────────────┘   └─────────────┘   └──────────────────────────────┘         │
│   （07）              （07）            （09）                                   │
└────────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────── 支撑机制（贯穿两链路）───────────────────────┐
│  · 组件编排机制（02）  · LLM 抽象可插拔（06）  · 组件/引擎清单（10）  │
│  · 评测与工程化（11）  · README 解读（00_01）                       │
└───────────────────────────────────────────────────────────────────┘
```

**三条主线一句话**：
- **离线链路**：把「文件」变成「知识库」——异步、可重跑、限流、可观测。
- **在线链路**：把「问题」变成「带引用的答案」——同步、低延迟、混合检索 + 重排。
- **支撑机制**：组件化、可插拔、评测 gate、生产级工程化。

## 三、建议学习路径（跟着一条文档走）

**路径原则**：不按文件目录读，按「一条文档从上传到被回答」读。每一步看到代码就画出来。

```
阶段 A  建立地图：00_架构与数据流总览 + 00_01_readme解读          （30 分钟）
阶段 B  离线链路（核心）：
   ① 数据接入调度 → 01（队列/限流/分派）
   ② 解析 → 03（DeepDoc 深度文档理解）
   ③ 分块 → 04（Chunker）
   ④ 分词向量 → 05（Tokenizer+Embedding）
   ⑤ 索引写入 → 08（chunk 结构 + 文档库）
         ⚡ 支撑：02（组件编排机制，讲清楚"组件怎么串起来"）
阶段 C  在线链路：
   ⑥⑦ 混合检索 + 重排 → 07（Dealer + Rerank）
   ⑧ 在线问答组装 → 09（retrieval + context + 引用）
         ⚡ 支撑：06（LLM 五类抽象，贯穿全程）
阶段 D  工程化：
   10（组件/引擎清单，回顾全貌）
   11（评测 + 限流 + 可观测）
   12（落到自己的 ai_assistant）
```

**对照自己项目**：每学一个阶段，问"我的 ai_assistant 缺这个吗？该怎么加？"——对应动作集中在 `12_对标ai_assistant_改造建议.md`。

## 四、RAGFlow 最值得学的东西（按价值排序）

1. **离线链路的生产级骨架**（01 + 02 + 08）：队列 + 消费者组 + 限流器 + 组件化 DAG + 批量写入——这就是"RAG 离线链路建设"的完整开源样板。
2. **DeepDoc 深度文档理解**（03）：版面分析 + 表格结构化 + OCR，是普通 RAG 和高质 RAG 的分水岭。
3. **混合检索 + 重排**（07 + 09）：向量 + BM25 fusion + 归一化重排 + 引用，召回质量的完整方案。
4. **LLM 五类抽象可插拔**（06）：chat/embedding/rerank/cv/ocr 各一接口，30+ provider。
5. **评测与工程化**（11）：Benchmark（ndcg@10/map@5/mrr@10）+ 限流 + 重试 + 可观测。

## 五、学习心法

1. **按数据流读，不按文件行数读**——跟着「上传 → 解析 → 分块 → 向量 → 索引 → 检索 → 回答」走。
2. **对照 `ai_assistant` 读**——RAGFlow 的每个组件，都是你"数据接入"该长成的样子。
3. **抓主干代码**——每个文件都是「真实代码 + 注释 + 作用 + 三问」，直接读代码，不读二手转述。
4. **RAGFlow 是双栈**：`rag/`（Python 主路径）+ `internal/`（Go 并行重构中）。以 Python 路径为主线。
