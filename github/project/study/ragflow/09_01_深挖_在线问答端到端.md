# 深挖：在线问答端到端（POST /chat/completions 全链路）

> 深挖 07_01 讲检索器 Dealer、08_01 讲 ES 连接器。本篇回答"**用户发一句话，到前端显示带引用的答案，中间到底发生了什么**"。
> 核心认知：**引用 ID 就是 top-K 数组下标**——`kb_prompt` 用 `enumerate` 的 `i` 生成 `ID: i`，答案里 `[ID:i]` 直接对应 `reference.chunks[i]`。LLM 忘了带引用时由 `insert_citations` 按语义相似度回补。
> 在线问答默认**不走画布**（reasoning=0 直连 `async_chat`）；画布是独立产品。但两者共用 `retriever.retrieval` / `citation_prompt` / `structure_answer`。

- 上游：深挖 07_01 的 `retriever.retrieval()`（search.py:580）
- 下游：SSE 帧 → 前端正则抓 `[ID:i]` → 高亮角标 → 点击定位原文

```python
def kb_prompt(kbinfos, max_tokens, hash_id=False):
    knowledges = []
    for i, ck in enumerate(kbinfos["chunks"][:chunks_num]):
        cnt = "\nID: {}".format(i if not hash_id else hash_str2int(get_value(ck, "id", "chunk_id"), 500))
        cnt += draw_node("Title", get_value(ck, "docnm_kwd", "document_name"))
        cnt += draw_node("URL", ck.get("url", ""))
        meta = ck.get("document_metadata") or {}
        for k, v in meta.items():
            cnt += draw_node(k, v)
        cnt += "\n└── Content:\n"
        cnt += get_value(ck, "content", "content_with_weight")
        knowledges.append(cnt)
    return knowledges
```

## 三、引用落地 —— `[ID:i]` → chunk 原文/位置 ★（dialog_service.py:853-895）

```python
# decorate_answer：把 [ID:i] 解析成 refs（LLM 已带则解析；没带则语义补引用）
async def decorate_answer(answer):
    if knowledges and (prompt_config.get("quote", True) and kwargs.get("quote", True)):
        idx = set([])
        normalized_answer = normalize_arabic_digits(answer) or ""
        if embd_mdl and not CITATION_MARKER_PATTERN.search(normalized_answer):
            # ① LLM 没生成引用 → 语义补引用：句子切分+embedding+hybrid similarity
            answer, idx = retriever.insert_citations(
                answer,
                [ck["content_ltks"] for ck in kbinfos["chunks"]],
                [ck["vector"] for ck in kbinfos["chunks"]],
                embd_mdl, tkweight=1-dialog.vector_similarity_weight, vtweight=dialog.vector_similarity_weight)
        else:
            # ② LLM 已生成 [ID:i] → 正则收集下标
            for match in CITATION_MARKER_PATTERN.finditer(normalized_answer):
                i = int(match.group(1))
                if i < len(kbinfos["chunks"]):
                    idx.add(i)
        answer, idx = repair_bad_citation_formats(answer, kbinfos, idx)   # 容错非标格式
        idx = set([kbinfos["chunks"][int(i)]["doc_id"] for i in idx])     # → doc_id 集合
        recall_docs = [d for d in kbinfos["doc_aggs"] if d["doc_id"] in idx]
        if not recall_docs:
            recall_docs = kbinfos["doc_aggs"]
        kbinfos["doc_aggs"] = recall_docs
        refs = deepcopy(kbinfos)                 # ★ 整份 kbinfos 作为引用返回
```

**作用（关键）**：引用落地两条路——LLM 已带 `[ID:i]` 直接正则解析；没带则 `insert_citations` 把答案切句、每句和 top-K 向量算 `hybrid_similarity`、取超阈值的 chunk 回补 `[ID:c]`。最终 `refs = deepcopy(kbinfos)`——**整份 kbinfos 作为引用返回**。

```python
def structure_answer(conv, ans, message_id, session_id):
    reference = ans["reference"]
    chunk_list = chunks_format(reference)          # 原始 chunk → 前端友好对象
    reference["chunks"] = chunk_list
    ans["id"], ans["session_id"] = message_id, session_id
    if not conv.message or conv.message[-1]["role"] != "assistant":
        conv.message.append({"role": "assistant", "content": content, "created_at": time.time(), "id": message_id})
    else:
        conv.message[-1] = {"role": "assistant", "content": ans["answer"], ...}
    if conv.reference:
        conv.reference[-1] = reference              # 引用与 assistant 消息一一对应落地
    return ans
```

```python
async def rag_agent(dialog, messages, stream=True, **kwargs):
```

## 九、对照 ai_assistant

| RAGFlow | 你的 ai_assistant | 差距 |
|---------|------------------|------|
| `[ID:i]` = top-K 数组下标引用体系 | 无引用 | ❌ 答案无出处 |
| LLM 带引用解析 + `insert_citations` 语义回补 | 无 | ⚠️ 忘带引用就无引用 |
| `<think>` 状态机 + 16 token 攒批流式 | 一次性返回 | ⚠️ 首字延迟高 |
| final 帧带 reference（中间帧空引用） | 无 | ⚠️ 引用时序设计 |
| 多轮追问 `full_question` 改写 | 原样多轮拼接 | ⚠️ 指代不清 |
| history 全量进 prompt + JSON 并行数组存引用 | 简单存消息 | 概念参考 |
| reasoning>0 agentic RAG 图 | 无 | 概念参考 |

**落地优先级**：
- **P0**：**引用体系**——检索结果编号（top-K 下标即 ID），LLM prompt 要求 `[ID:x]`，答案附引用块。这是 RAG 可信度的命门。
- **P1**：**SSE 流式**——逐 token 下发 + final 帧带引用。
- **P2**：`insert_citations` 语义回补（LLM 忘带引用时按句相似度补）+ 多轮追问改写。

## 十、总结

| 环节 | 代码 | 作用 |
|------|------|------|
| 入口 | `session_completion`（chat_api:1230） | 归一化 + 加载会话 |
| 分流 | `rag_agent`（dialog:1931） | reasoning=0 直连 / >0 走 agentic |
| 检索 | `retriever.retrieval`（search:580） | 混合检索+重排 → kbinfos |
| context | `kb_prompt`（generator:139） | chunk → ID:i 块 → {knowledge} |
| 引用指令 | `citation_prompt`（generator:214） | prompt 尾引用规则 |
| 生成 | `async_chat_streamly_delta` | 逐 token 流式 |
| 引用落地 | `decorate_answer`（dialog:853） | 解析 [ID:i] / insert_citations |
| 归一化 | `structure_answer`（conv:188） | chunks_format + 写回 conv |
| 存储 | `Conversation`（db_models:1479） | message/reference JSON 并行数组 |
| SSE | chat_api:1331 | 中间帧空引用 + final 帧带引用 |

**一句话心法**：**在线问答 = 检索上下文 + 引用编号 + 流式生成 + 引用落地**四段式。引用体系的精髓是"**ID 即数组下标**"——`ID:i` 对应 `reference.chunks[i]`，前后端按位置而非 id 对齐，简单可靠；LLM 忘带引用就按语义相似度回补。流式的精髓是"中间帧只吐增量、引用放 final 帧"，前端看 `final` 标志区分。
