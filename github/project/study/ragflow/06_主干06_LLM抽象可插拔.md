# 主干 ⑥：LLM 抽象（可插拔）

> 这是 RAGFlow 的「可插拔」核心——chat / embedding / rerank / cv / ocr 五类模型，各自一个 Base 接口 + 30+ provider 实现。
> 对照 Vanna 的 `LlmService` 抽象：思想一样（接口 vs 实现分离），但 RAGFlow 拆得更细（五类模型）。

## 三问

- **Q1 解决什么问题**：把「换 LLM / 换 embedding / 换重排模型」变成"改配置"，不改主流程。
- **Q2 数据流哪一环**：贯穿全链路——离线用 embedding/cv/ocr，在线用 chat/rerank。
- **Q3 删掉会怎样**：每个 provider 一套代码，Agent/ingestion 强耦合，换模型要改一堆。

---

## 一、五类模型抽象（rag/llm/）

| 模型类型 | Base 文件 | 核心方法 | 用在哪 |
|---------|----------|---------|--------|
| **chat** | `chat_model.py` | `async_chat_streamly` / `chat` | 在线生成 + Agent |
| **embedding** | `embedding_model.py` | `encode` / `encode_queries` | 离线向量化 + 在线 query 向量 |
| **rerank** | `rerank_model.py` | `similarity(query, texts)` | 在线重排 |
| **cv（视觉）** | `cv_model.py` | 图片理解 | 图表语义描述 |
| **ocr** | `ocr_model.py` | 文字识别 | 扫描件 |

**核心**：五类模型各有一个 `Base(ABC)` 接口，30+ provider 子类实现同一接口，`LLMBundle` 按配置实例化对应子类，上层只认 Base。

## 二、Chat Base（rag/llm/chat_model.py:232）

```python
class Base(ABC):
    def __init__(self, key, model_name, base_url, **kwargs):
        # ★ 统一用 OpenAI 客户端（openai 包兼容大部分 provider 的 OpenAI 接口）
        self.client = OpenAI(api_key=key, base_url=self.base_url, timeout=timeout)
        self.async_client = AsyncOpenAI(api_key=key, base_url=self.base_url, timeout=timeout)
        self.model_name = model_name
        # ★ 重试参数
        self.max_retries = kwargs.get("max_retries", int(os.environ.get("LLM_MAX_RETRIES", 5)))
        self.base_delay = kwargs.get("retry_interval", float(os.environ.get("LLM_BASE_DELAY", 2.0)))

    def _classify_error(self, error):
        """把各种 provider 的错误字符串 → 统一错误码"""
        keywords_mapping = [
            (["quota", "billing", "欠费"], LLMErrorCode.ERROR_QUOTA),
            (["rate limit", "429", "too many requests"], LLMErrorCode.ERROR_RATE_LIMIT),
            (["auth", "401", "forbidden"], LLMErrorCode.ERROR_AUTHENTICATION),
            (["timeout", "timed out"], LLMErrorCode.ERROR_TIMEOUT),
            ...
        ]
        for words, code in keywords_mapping:
            if re.search("({})".format("|".join(words)), error_str):
                return code
        return LLMErrorCode.ERROR_GENERIC

    async def async_chat_streamly(self, system, history, gen_conf, **kwargs):
        """流式对话：for attempt in range(max_retries+1) 重试循环"""
        for attempt in range(self.max_retries + 1):
            try:
                async for delta_ans, tol in self._async_chat_streamly(history, gen_conf, **kwargs):
                    yield delta_ans          # 逐 token 流出
                return
            except Exception as e:
                e = await self._exceptions_async(e, attempt)   # 分类错误 → 判断是否重试
                if e:
                    yield e; return
```

**作用（关键）**：
1. **统一 OpenAI 客户端**：`OpenAI(api_key, base_url)` —— 因为 90% 的 LLM provider 都提供 OpenAI 兼容接口，RAGFlow 用一个客户端接 30+ provider。
2. **错误分类 + 重试**：`_classify_error` 把错误字符串归类（quota/rate_limit/auth/timeout...），`_retryable_errors` 只对 rate_limit/server 重试，其余直接抛。**这是生产级 LLM 调用的标准做法**。
3. **流式**：`async_chat_streamly` 逐 token yield，支持打字机效果。

## 三、Rerank Base（rag/llm/rerank_model.py:34）

```python
class Base(ABC):
    def similarity(self, query: str, texts: List) -> Tuple[np.ndarray, int]:
        """统一入口：打分 + 归一化到 [0,1]"""
        if not query or not texts:
            return np.zeros(len(texts) if texts else 0, dtype=float), 0
        rank, token_count = self._compute_rank(query, texts)   # 子类实现打分
        rank = np.asarray(rank, dtype=float)
        return self._normalize_rank(rank), token_count         # ★ 归一化

    def _compute_rank(self, query: str, texts: List):
        raise NotImplementedError("Please implement _compute_rank method!")

    @staticmethod
    def _normalize_rank(rank: np.ndarray) -> np.ndarray:
        """把任意 provider 的分数归一到 [0,1]"""
        min_rank, max_rank = float(np.min(rank)), float(np.max(rank))
        if min_rank >= 0.0 and max_rank <= 1.0:
            return rank                    # 已经是 [0,1]（Cohere/Jina）→ 不处理
        span = max_rank - min_rank
        if span < 1e-3:
            return np.clip(rank, 0.0, 1.0) # 无区分度 → 截断
        return (rank - min_rank) / span    # min-max 归一化
```

**作用（关键）**：
1. **统一打分入口** `similarity()`：子类只实现 `_compute_rank`（怎么打分），父类统一做空输入处理 + 归一化。
2. **归一化到 [0,1]**：不同 provider 打分尺度不同（Cohere 是 [0,1] 相关度，NVIDIA 是无界 logits），统一归一化后，混合检索的加权（`vtweight`）才不会错。**这是生产级重排的关键细节**——你之前说的"重排分数要和向量/关键词分数融合"，前提就是统一尺度。

## 四、可插拔的本质（对照 Vanna）

```
上层（ingestion / retrieval / Agent）只认 Base 接口
  │
  ├─ chat:      Base ← OpenAI_APIChat / GoogleChat / MistralChat / ...
  ├─ embedding: Base ← OpenAIEmbed / DashScopeEmbed / OllamaEmbed / ...
  ├─ rerank:    Base ← JinaRerank / CoHereRerank / NvidiaRerank / ...
  ├─ cv:        Base ← ...
  └─ ocr:       Base ← ...
```

**换模型 = 改配置**，`LLMBundle` 按 `tenant_id + model_config` 从 registry 实例化对应子类，上层一行不改：

```python
# 同一个 embedding 调用，不同配置注入不同实现
embedding_model = LLMBundle(tenant_id, embd_model_config)  # 配置里是 OpenAI 还是 BGE 都行
vts, _ = embedding_model.encode([...])                       # 只认 Base.encode
```

**对照 Vanna**：Vanna 是 `LlmService`（chat 一个接口）+ `SqlRunner`（数据库一个接口）；RAGFlow 是**五类模型接口**（因为 RAG 需要 chat/embedding/rerank/cv/ocr 五类）。思想完全一致：**接口是插座，实现是插头，上层只认插座**。

## 五、总结

| 概念 | 代码 | 作用 |
|------|------|------|
| Chat Base | `chat_model.py:232` | 统一 OpenAI 客户端 + 错误分类重试 + 流式 |
| Embedding Base | `embedding_model.py:147` | encode / encode_queries 分离 |
| Rerank Base | `rerank_model.py:34` | similarity 统一入口 + 归一化 |
| 错误分类 | `_classify_error` | 区分可重试/不可重试错误 |
| 30+ provider | 各子类 | 换模型=换类，上层不改 |

**核心心法**：**可插拔 = 五类模型接口 + provider 子类 + LLMBundle 装配**。你的 ai_assistant 如果 `llm_client` 只写死一个 OpenAI，就该按"接口 + 多实现"重构——至少 chat/embedding/rerank 三个接口分开，才能在生产环境自由换模型。
