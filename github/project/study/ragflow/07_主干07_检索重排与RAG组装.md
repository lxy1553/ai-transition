# 主干 ⑦：检索 + 重排（在线链路前半）

> 这是 RAG 的**在线链路前半**——query 进来，怎么从文档库召回最相关的 chunk 并重排精排。
> 对照你上一个问题「在线检索」，这里就是"写入之后怎么查"。
> **RAG 组装 + 引用 + 流式**见 `09_在线问答与RAG组装.md`（后半）。

## 三问

- **Q1 解决什么问题**：query → 混合检索（向量 + 关键词）→ 重排，拿到最相关的 top-K chunk。
- **Q2 数据流哪一环**：在线链路全部——离线产出的文档库在这里被消费。
- **Q3 删掉会怎样**：有知识库也搜不出来，RAG 退化成纯 LLM。

---

## 一、在线链路数据流图

```
用户 query
  │
  ▼
① query 向量化（embedding.encode_queries）
  │
  ▼
② Dealer.search（rag/nlp/search.py）
  │  混合检索：向量(cosine) + full_text(BM25) → weighted_sum fusion
  │  产出：top-N 候选 chunk（含相似度分数）
  ▼
③ Rerank 重排（rag/llm/rerank_model + Dealer.rerank_by_model）
  │  精排：query 和每个候选重新打分，取 top-K
  ▼
（④⑤ 拼上下文 + LLM 生成 + 引用 → 见 09_在线问答与RAG组装.md）
```

## 二、Dealer 检索器（rag/nlp/search.py）

### ① 混合检索表达式 build_fusion_expr（search.py:35）

```python
def build_fusion_expr(topn: int, vector_similarity_weight: float = 0.3) -> FusionExpr:
    """向量 + 关键词的加权融合表达式"""
    term_similarity_weight = 1 - vector_similarity_weight
    return FusionExpr(
        "weighted_sum", topn,
        {"weights": f"{term_similarity_weight:g},{vector_similarity_weight:g}"},
    )
```

**作用（关键）**：**混合检索 = 向量相似度 + 关键词相似度的加权和**。默认 `vector_similarity_weight=0.3`，即 **0.7 关键词 + 0.3 向量**——注意关键词权重更高，因为精确术语/编号靠 BM25 更准（对应你之前说的"混合检索比纯向量强"）。

### ② query 向量化 get_vector（search.py:65）

```python
async def get_vector(self, txt, emb_mdl, topk=10, similarity=0.1):
    # ① query → 向量（用 encode_queries，非对称检索）
    qv, _ = await thread_pool_exec(emb_mdl.encode_queries, txt)
    # ② 向量列名动态：q_{维度}_vec，和写入时对齐
    vector_column_name = f"q_{len(embedding_data)}_vec"
    # ③ 构造向量检索表达式：cosine 相似度，topk，相似度阈值
    return MatchDenseExpr(vector_column_name, embedding_data, "float", "cosine", topk,
                          {"similarity": similarity})
```

**作用**：query 向量化后构造向量检索表达式，`cosine` 相似度 + `similarity` 阈值（过滤低相关）。`q_{dim}_vec` 和离线写入时的动态字段对齐。

### ③ 检索主入口 search（search.py:144）

```python
async def search(self, req, idx_names, kb_ids, emb_mdl=None, highlight=None, ...):
    filters = self.get_filters(req)      # kb_id / doc_id 过滤（租户隔离）
    topk = int(req.get("topk", 1024))    # 召回候选数
    # fields：返回的 chunk 字段（含 page_num_int/position_int 供引用定位）
    src = req.get("fields", ["docnm_kwd", "content_ltks", "kb_id", "img_id",
                             "title_tks", "position_int", "doc_id",
                             "chunk_order_int", "page_num_int", ...])
    # → 交给 DocStoreConnection（ES/Infinity）执行混合检索
    ...
```

**作用**：
- **过滤**：`get_filters` 按 `kb_id`/`doc_id` 过滤，实现**租户/知识库隔离**（对应 Vanna 的权限层）。
- **topk=1024**：先粗召回 1024 个候选，再交给重排精排 top-K（两阶段检索）。
- **fields 含位置元数据**：`page_num_int`/`position_int` 支持前端"引用定位"。

### ④ 过滤已删除文档 _prune_deleted_chunks（search.py:87）

```python
async def _prune_deleted_chunks(self, sres: SearchResult) -> SearchResult:
    """删除路径可能残留脏 chunk，检索后过滤掉已删除文档的 chunk"""
    chunk_doc_ids = [chunk.get("doc_id") for chunk in sres.field.values()]
    existing_doc_ids = await self._existing_doc_ids(chunk_doc_ids)   # 查 DB 确认文档还在
    # 过滤：doc_id 不在 existing_doc_ids 里的 chunk 全删
```

**作用**：这是**生产级兜底**——删除文档时如果向量库没清理干净，检索会捞出"幽灵 chunk"。这里检索后再过滤一遍，保证不返回已删内容。

## 三、Rerank 重排（rag/llm/rerank_model.py）

### Base.similarity（rerank_model.py:38）—— 已学（主干⑥）

```python
def similarity(self, query: str, texts: List):
    rank, token_count = self._compute_rank(query, texts)   # 子类打分
    return self._normalize_rank(rank), token_count         # 归一化到 [0,1]
```

**作用**：**两阶段检索的第二阶段**——Dealer 粗召回 1024 个候选，Rerank 用更强的模型（Cross-Encoder 类）对 query 和每个候选**联合打分**，精排取 top-K（比如 5 个）。粗排靠向量（快），精排靠重排（准）。

## 五、总结

| 环节 | 代码 | 作用 |
|------|------|------|
| 混合检索 fusion | `build_fusion_expr` | 向量 + 关键词加权和（0.3/0.7） |
| query 向量化 | `get_vector` | encode_queries + cosine 相似度 |
| 检索主入口 | `search` | kb/doc 过滤 + topk 粗召回 |
| 脏数据过滤 | `_prune_deleted_chunks` | 过滤已删除文档的 chunk |
| 重排 | `rerank_model.py:38` + `rerank_by_model` | 精排 + 归一化 + 分数融合 |

**核心心法**：在线链路是**「混合粗召回（向量+BM25）→ 重排精排」两阶段检索**。你的 ai_assistant 如果只做"向量 top-K 直接喂 LLM"，就缺了"混合检索 + 重排"这两步——这是召回质量的最大提升点。后续组装见 `09_在线问答与RAG组装.md`。

## 附：离线链路的完整串联（七主干回顾）

```
① TaskExecutor(消费队列) → ② Pipeline(组件编排)
  → ③ Parser(解析) → ④ Chunker(分块)
  → ⑤ Tokenizer+Embedding(分词+向量化) → 写入文档库
  (⑥ LLM 抽象贯穿全程)
─────────────────────────────────────────────
  → ⑦ Dealer.search(混合检索) → Rerank(重排) → LLM(生成)
```

> 这七步，就是你上一个问题「RAG 离线链路 + 在线检索」在 RAGFlow 里的完整落地。
