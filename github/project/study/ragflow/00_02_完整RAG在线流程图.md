# 完整 RAG 在线流程图：问题进来 → 最终回答（代码块 + 注释）

> 这是把全部深挖串成一条线的**总图**。按 RAGFlow 源码实际调用链走一遍：用户敲下一句话，到前端显示带引用、可点击定位原文的答案，一共 **10 站**。
> 核心认知：**整条链路 = 入口分流 → 查询改写 → 混合检索 → 重排 → 拼 context → LLM 流式生成 → 引用落地 → 结构化持久化 → SSE 下发**。每条深挖都是其中一站。
> ⚠️ 默认 `reasoning=0` 时**直连 `async_chat`（经典 RAG），不走 agent 画布**；`reasoning>0` 才在 chat 内部起 agentic RAG 图。
> 引用 ID 的真相：**`ID:i` 就是 top-K 数组下标 `i`**，`[ID:i]` 直接对应 `reference.chunks[i]`。

- 主链源码：`api/apps/restful_apis/chat_api.py` → `api/db/services/dialog_service.py` → `rag/nlp/search.py` → `rag/prompts/generator.py` → `rag/nlp/{query,rerank,rag_tokenizer}.py` → `api/db/services/conversation_service.py`
- 对接深挖：`07_01`（检索器）· `08_01`（ES 连接器）· `09_01`（问答端到端）· `05_01`（分词）· `11_02`（KG 可选检索）

## ② 分流 —— rag_agent（dialog_service.py:1931）

```python
async def rag_agent(dialog, messages, stream=True, **kwargs):
    prompt_config = dialog.prompt_config or {}
    assert messages[-1]["role"] == "user", "最后一条必须是用户消息"
    reasoning = kwargs["reasoning"] if "reasoning" in kwargs else prompt_config.get("reasoning", 0)
    if not reasoning or str(reasoning).strip() == "0":
        async for ans in async_chat(dialog, messages, stream, **kwargs):   # ← 经典 RAG，主路径
            yield ans
        return
    # reasoning>0：agentic RAG 图（RAGTools 工具 + StateGraph，多跳工具调用）
    rag_tools = RAGTools(tenant_ids, chat_mdl, embed_mdl=embd_mdl, kb_ids=dialog.kb_ids, ...)
    chat_mdl.bind_tools(None, rag_tools.tools)
    chat_mdl.mdl.terminal_tools = {"rag"}      # rag 工具视为终态：直接流式其结果
```

**作用**：`reasoning=0` → 直连 `async_chat`（**这就是在线问答默认路径，与画布无关**）；`reasoning>0` → 起 agentic RAG 图（`formalize_question → route → planner → orchestrator_loop → formalize_answer`）。

```python
async def async_chat_streamly_delta(chat_mdl, system, messages, gen_conf, **kwargs):
    stream_iter = chat_mdl.chat(system, messages, gen_conf)        # 底层 LLM 流式迭代器
    async for kind, value, state in _stream_with_think_delta(stream_iter):   # <think> 状态机 + 攒批
        if kind == "marker":
            flags = {"start_to_think": True} if value == "<think>" else {"end_to_think": True}
            yield {"answer": "", "reference": {}, "final": False, **flags}
            continue
        yield {"answer": value, "reference": {}, "final": False}   # 中间帧：只吐增量，引用为空
    # 流结束后算引用，final 帧补发
    if full_answer:
        final = await decorate_answer(...)                          # ← 第⑧站
        final["final"] = True
        final["answer"] = ""                                        # ★ final 帧 answer 置空
        yield final
```

**作用**：逐 token 吐增量；`_stream_with_think_delta`（dialog_service.py:1621）处理 `<think>` 边界并按 16 token 攒批防碎片；**中间帧 `reference={}`，引用集中在 final 帧下发**——前端靠 `final` 标志区分增量与终态。

## ⑨ 结构化 + 持久化 —— structure_answer（conversation_service.py:188）

```python
def structure_answer(conv, ans, message_id, session_id):
    reference = ans["reference"]
    chunk_list = chunks_format(reference)          # 原始 chunk → 前端友好对象 ★
    reference["chunks"] = chunk_list
    ans["id"], ans["session_id"] = message_id, session_id
    # assistant 消息写回 conv.message（流式时逐帧 append 增量）
    if not conv.message or conv.message[-1]["role"] != "assistant":
        conv.message.append({"role": "assistant", "content": content, "created_at": time.time(), "id": message_id})
    else:
        if is_final:
            conv.message[-1] = {"role": "assistant", "content": ans["answer"], ...}   # final 帧整体覆盖
        else:
            conv.message[-1]["content"] = (conv.message[-1].get("content") or "") + content  # 增量拼接
    if conv.reference:
        if is_final or reference.get("chunks") or reference.get("doc_aggs"):
            conv.reference[-1] = reference          # ★ 引用与 assistant 消息一一对应
    return ans
```

## 对照 ai_assistant

| 站点 | RAGFlow | 你的 ai_assistant | 优先级 |
|------|---------|------------------|--------|
| ③ 查询改写 | `full_question` 多轮补全 + `keyword_extraction` | 原样拼接多轮 | P1 |
| ④ 混合检索 | 全文 + 向量 + 融合三段 | 纯向量或纯 BM25 | **P0** |
| ⑤ 重排 | 权重融合 + 外部模型归一化 | 无 | **P0** |
| ⑥ 引用编号 | `ID:i` = top-K 下标 | 无引用 | **P0** |
| ⑦ 流式 | `<think>` 状态机 + 攒批 | 一次性返回 | P1 |
| ⑧ 引用回补 | `insert_citations` 语义兜底 | 无 | P2 |
| ⑨ 持久化 | message/reference 并行数组 | 简单存消息 | P1 |
| ⑩ 前端 | 角标高亮 + 定位原文 | 纯文本 | **P0** |

**落地顺序**：先补 **P0**——混合检索 + 重排（召回质量）+ 引用编号与高亮（可信度）。再上 **P1**——流式 + 查询改写 + 并行数组持久化。最后 **P2** 引用语义回补。

## 一句话心法

**完整 RAG 在线链路 = 一句改写 + 三路召回 + 一层重排 + 一份带编号的 context + 一次流式生成 + 一段引用落地 + 一对并行数组持久化**。抓住四个精髓就能复刻：
1. **检索**：全文召回、向量排序、按权重融合（深挖 07/08）；
2. **引用**：`ID:i` 就是数组下标，LLM 忘带就按语义回补（深挖 09）；
3. **流式**：中间帧只吐增量、final 帧带引用，前端看 `final` 区分；
4. **闭环**：多轮 history 进 prompt、追问先改写指代、引用与消息等长并行存。
