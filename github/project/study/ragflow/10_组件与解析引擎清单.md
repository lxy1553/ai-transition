# RAGFlow 组件与解析引擎清单（全部核实）

> 基于 `rag/flow/`、`agent/component/`、`rag/flow/parser/parser.py`、`task_executor.py` 实际代码查证。
> 每个组件 = 名字 + 职责 + 在数据流哪一环。

---

## 一、Ingestion 组件（rag/flow/，7 个）

这是「可编排 ingestion pipeline」的组件库，可在 Canvas 拖拽串联：

| 组件名 | 文件 | 职责 | 数据流位置 |
|--------|------|------|-----------|
| **File** | `file.py` | 取原始文档（doc_id / file 双来源） | 起点 |
| **Parser** | `parser/parser.py` | 按后缀分派解析（13 种格式 × 9 引擎） | File → Parser |
| **TokenChunker** | `chunker/token_chunker.py` | 分隔符/token 分块 + overlap + 表格上下文 | Parser → Chunker |
| **TitleChunker** | `chunker/title_chunker/title_chunker.py` | 按标题层级分块（hierarchical） | Parser → Chunker（备选） |
| **Tokenizer** | `tokenizer/tokenizer.py` | 多路分词 + embedding 向量化 | Chunker → Tokenizer |
| **Extractor** | `extractor/extractor.py` | 实体/标签抽取（知识图谱用） | Tokenizer → Extractor |
| **Compiler** | `compiler/compiler.py` | 汇总/编译最终 chunk 结构 | 末端 |

> 核心链路：**File → Parser → Chunker → Tokenizer**（Extractor/Compiler 是可选的进阶组件）。

## 二、文档解析引擎（9 个，可插拔）

在 `Parser._pdf` 等分支里，按 `parse_method` 选择：

| 引擎 | parse_method | 特点 | 适用 |
|------|-------------|------|------|
| **DeepDoc（自研）** | `deepdoc` | 版面分析 + OCR + 表格，质量最高 | 默认，复杂文档 |
| **PlainParser** | `plain_text` | 只抽文本，最快 | 简单纯文本 |
| **MinerU** | `mineru` | 外部 OCR 模型（LLMBundle） | 扫描件、公式 |
| **Docling** | `docling` | IBM 开源，版面理解强 | 结构化文档 |
| **OpenDataLoader** | `opendataloader` | 开源数据加载器 | 通用 |
| **PaddleOCR** | `paddleocr` | 国产 OCR，中文强 | 中文扫描件 |
| **SoMark** | `somark` | 多模态 OCR | 复杂版面 |
| **Mistral OCR** | `mistral ocr` | Mistral 多模态 | 复杂版面 |
| **TCADP** | `tcadp parser` | 腾讯云解析 | 腾讯云生态 |

> 对应 Vanna 的「集成可插拔」：换解析引擎 = 改 `parse_method` 配置，`Parser` 主流程不变。

## 三、文档类型模板（FACTORY，14 种）

`rag/svr/task_executor.py:111` 的 FACTORY，按用户选的 parser_type 分派：

| parser_type | 模块 | 分块策略 |
|-------------|------|---------|
| general | `naive` | 通用（token 分块） |
| paper | `paper` | 论文（按标题层级） |
| book | `book` | 书籍（按章节） |
| laws | `laws` | 法律（按条款） |
| qa | `qa` | 问答对 |
| table | `table` | 表格 |
| resume | `resume` | 简历（按字段） |
| picture | `picture` | 图片（OCR/VLM） |
| one | `one` | 整篇一个 chunk |
| audio | `audio` | 音频（转写） |
| email | `email` | 邮件（按收发件） |
| presentation | `presentation` | PPT |
| manual | `manual` | 手册（按目录） |
| kg / tag | `naive` / `tag` | 知识图谱 / 标签 |

> 这就是 README 说的「**模板化分块**」——不同文档类型，不同解析 + 分块策略。

## 四、Agent 组件（agent/component/，24 个）

RAGFlow 的 Agent 层（Canvas 工作流），对应 Vanna 的「Tool 清单」：

| 组件 | 职责 |
|------|------|
| begin | 工作流起点 |
| message | 发消息 |
| llm | 调 LLM（生成/推理） |
| agent_with_tools | 带工具的 Agent 循环 |
| switch | 条件分支 |
| loop / loopitem | 循环 |
| iteration / iterationitem | 迭代 |
| categorize | 分类 |
| browser | 浏览器操作 |
| excel_processor | Excel 处理 |
| data_operations | 数据操作 |
| string_transform | 字符串转换 |
| variable_assigner / variable_aggregator | 变量赋值/聚合 |
| fillup / docs_generator | 填充/文档生成 |
| exit_loop | 退出循环 |

> 对应 Vanna：Vanna 的 Agent 是"LLM + 工具循环"；RAGFlow 的 Agent 是"Canvas 工作流 + 组件"，组件是**预定义的处理节点**（不是 LLM 自主选的工具），更适合确定性的企业工作流。

## 六、组件怎么配合（数据流全图）

```
用户上传 PDF（选 parser_type=paper）
  │
  ▼
TaskExecutor → FACTORY[paper] → paper.chunk()
  │
  ├─ by_deepdoc → Pdf → RAGFlowPdfParser（版面分析+OCR+表格）
  │    产出：sections(文本块) + tables(结构化表格)
  ├─ 按论文标题层级分块
  ├─ Tokenizer：多路分词 + embedding
  └─ 写入 ES/Infinity（chunk + 向量 + 关键词 + 元数据）
  ▼
用户 query → Dealer.search（混合检索）→ Rerank → LLM 生成（带引用）
```

## 七、对照 ai_assistant 的改造动作

| 你现在 | RAGFlow 式改造 |
|--------|---------------|
| 1 个"读文本/SQL"能力 | 拆成 Parser（多引擎）+ Chunker（模板）+ Tokenizer+Embedding |
| 固定分块 | 按文档类型模板分块（FACTORY） |
| 纯向量检索 | Dealer 混合检索（向量+BM25）+ Rerank |
| 写死一个 LLM | 五类 LLM 接口可插拔 |
| 同步执行 | TaskExecutor 队列 + 限流器 |

**核心**：一个组件 = 一个职责 = 统一接口。组件拆得越细，越能复用、测试、编排。
