# 深挖：ES 连接器内部（rag/utils/es_conn.py + common/doc_store/）

> 这是深挖 07_01 里 `dataStore.search()` 的落点——回答"**检索表达式怎么变成 ES 查询 DSL，向量检索怎么在 ES 里跑**"。
> RAGFlow 的思路：上层只认 **DocStoreConnection 抽象接口 + 表达式对象（MatchTextExpr/MatchDenseExpr/FusionExpr）**，ESConnection 负责把它们翻译成 `bool + query_string + knn` 三段式 DSL。
> 引擎可换（ES/Infinity/GaussDB…），上层零改动——这是"存储抽象"的完整样板。

- 源码位置：`github/project/ragflow/rag/utils/es_conn.py` + `common/doc_store/{doc_store_base,es_conn_base,es_conn_pool}.py` + `conf/mapping.json`
- 上游：深挖 07_01 的 `Dealer.search`（rag/nlp/search.py:205）构造表达式 → `dataStore.search`
- 下游：ES 返回 `hits` → `get_highlight/get_fields/get_doc_ids` 装配 `SearchResult`
- ⚠️ 本版本差异：**无 `common/struct/expr.py`**（表达式并入 `doc_store_base.py:58-145`）、**无 `MatchDateExpr`**（日期检索走 condition + `*_dt` date 模板）

---

## 三问

- **Q1 解决什么问题**：让"检索"不绑定具体数据库。上层写"我要全文+向量+权重融合"，ESConnection 翻译成 ES 能懂的 DSL。
- **Q2 数据流哪一环**：在线链路检索阶段——`Dealer.search` 造表达式 → 连接器翻译 → ES 查询 → 结果装配回 `SearchResult`。
- **Q3 删掉会怎样**：换引擎（Infinity/OceanBase）时上层全要改——存储抽象就是为"多引擎可插拔"而生的。

## 一、`DocStoreConnection` 抽象接口 —— 门面（doc_store_base.py:148-277）

```python
class DocStoreConnection(ABC):
    @abstractmethod
    def db_type(self) -> str: ...
    @abstractmethod
    def health(self) -> dict: ...
    @abstractmethod
    def create_idx(self, index_name, dataset_id, vector_size, parser_id=None): ...
    @abstractmethod
    def search(self, select_fields, highlight_fields, condition, match_expressions,
               order_by, offset, limit, index_names, dataset_ids,
               agg_fields=None, rank_feature=None): ...
    @abstractmethod
    def insert(self, rows: list[dict], index_name, dataset_id=None) -> list[str]: ...
    @abstractmethod
    def update(self, condition, new_value, index_name, dataset_id) -> bool: ...
    @abstractmethod
    def delete(self, condition, index_name, dataset_id) -> int: ...
    # 结果辅助：get_total / get_doc_ids / get_fields / get_highlight / get_aggregation / sql
```

**作用**：所有文档库操作都定义成抽象方法。上层全局单例 `settings.docStoreConn`（common/settings.py:401）按 `DOC_ENGINE` 环境变量实例化 ES/Infinity/OpenSearch/OceanBase/GaussDB 实现——**上层永远只碰这个门面**。

**表达式类**也定义在同一文件（doc_store_base.py:58-145）：
- `MatchTextExpr`（全文：fields + matching_text + extra_options 里的 minimum_should_match）
- `MatchDenseExpr`（向量：vector_column_name + embedding_data + similarity 阈值）
- `FusionExpr`（融合：method="weighted_sum" + weights）
- `OrderByExpr`（排序）

## 二、`search` 三段式翻译 —— 表达式 → ES DSL ★（es_conn.py:179-277）

### ① condition 字典 → bool filter（es_conn.py:201-231）

```python
bool_query = Q("bool", must=[])
condition["kb_id"] = knowledgebase_ids          # ★ 强制注入：一个租户一个索引，kb 靠 kb_id 过滤
for k, v in condition.items():
    if k == "available_int":                     # 特殊分支 → range
        if v == 0:
            bool_query.filter.append(Q("range", available_int={"lt": 1}))
        else:
            bool_query.filter.append(Q("bool", must_not=Q("range", available_int={"lt": 1})))
        continue
    if isinstance(v, list):
        bool_query.filter.append(Q("terms", **{k: v}))
    elif isinstance(v, str) or isinstance(v, int):
        bool_query.filter.append(Q("term", **{k: v}))
    else:
        raise Exception(...)
```

**作用**：`kb_id/doc_id` 等元数据条件翻译成 `term/terms` 过滤，`available_int`（块是否可检索）翻译成 `range`。

### ② MatchTextExpr → query_string + MatchDenseExpr → knn（es_conn.py:246-266）

```python
if isinstance(m, MatchTextExpr):
    minimum_should_match = (m.extra_options or {}).get("minimum_should_match", 0.0)
    if isinstance(minimum_should_match, float):
        minimum_should_match = str(int(minimum_should_match * 100)) + "%"   # 0.3 → "30%"
    bool_query.must.append(Q("query_string", fields=m.fields, type="best_fields",
                             query=m.matching_text,
                             minimum_should_match=minimum_should_match, boost=1))
    bool_query.boost = 1.0 - vector_similarity_weight      # ★ 全文权重被融合权重压制
elif isinstance(m, MatchDenseExpr):
    k = min(m.topn, 10000)
    s = s.knn(
        m.vector_column_name, k, min(k * 2, 10000),
        query_vector=list(m.embedding_data),
        filter=bool_query.to_dict(),                        # ★ knn 带 bool 过滤
        similarity=m.extra_options["similarity"],           # ★ 余弦阈值（默认 0.1）
    )
```

### ③ FusionExpr → 只提取向量权重（es_conn.py:236-244）

```python
for m in match_expressions:
    if isinstance(m, FusionExpr) and m.method == "weighted_sum" and "weights" in m.fusion_params:
        assert (len(match_expressions) == 3 and isinstance(match_expressions[0], MatchTextExpr)
                and isinstance(match_expressions[1], MatchDenseExpr)
                and isinstance(match_expressions[2], FusionExpr))
        weights = m.fusion_params["weights"]
        vector_similarity_weight = get_float(weights.split(",")[1])   # 只取向量权重
```

**作用（关键）**：**融合不在 ES 里做**——ES 没有原生的 weighted_sum。它用 `bool_query.boost = 1 - vector_weight` 调 query_string 的权重，knn 用相似度阈值过滤，**引擎内粗排，引擎外二次精确融合**（见深挖 07_01 的 rerank_with_knn）。

最后拼 DSL：`s.query(bool_query).highlight(...).sort(...).source(...)[offset:offset+limit]` → `s.to_dict()` 提交（es_conn.py:274-308）。

## 三、向量检索三要素（search.py:65-72 + es_conn.py:253-266）

```python
async def get_vector(self, txt, emb_mdl, topk=10, similarity=0.1):     # search.py:65
    qv, _ = await thread_pool_exec(emb_mdl.encode_queries, txt)
    embedding_data = [get_float(v) for v in qv]
    vector_column_name = f"q_{len(embedding_data)}_vec"    # ★ 按向量维度命名：q_768_vec
    return MatchDenseExpr(vector_column_name, embedding_data, "float", "cosine", topk,
                          {"similarity": similarity})
```

**三要素**：
1. **字段 = dense_vector**（mapping 中 `similarity: cosine`，见第 5 点动态模板）
2. **查询 = knn**（`s.knn(...)` 原生 query，带 bool 过滤）
3. **余弦阈值 = knn 的 `similarity` 参数**（默认 0.1，空结果时放宽到 0.17）

**二次 KNN 取分**（search.py:394-425）：重排阶段只按候选 id 过滤再跑一次纯 KNN（不取 `_source` 只取 `_id/_score`），拿到每个 chunk 的干净余弦分，供 `rerank_with_knn` 混合——**避免把整条向量拉出引擎**。

## 四、高亮 `get_highlight` —— `<em>` 回填（es_conn_base.py:324-346）

```python
def get_highlight(self, res, keywords, field_name):
    ans = {}
    for d in res["hits"]["hits"]:
        highlights = d.get("highlight")
        if not highlights:
            continue
        txt = "...".join([a for a in list(highlights.items())[0][1]])   # 取第一个高亮字段片段
        if not is_english(txt.split()):           # 非英文直接用 ES 片段（ltks 已切好）
            ans[d["_id"]] = txt
            continue
        txt = d["_source"][field_name]            # 英文：基于原始 content 重扫
        for t in re.split(r"[.?!;\n]", txt):
            for w in keywords:
                t = re.sub(r"(^|[ .?/'\"()!,:;-])(%s)([ .?/'\"()!,:;-])" % re.escape(w),
                           r"\1<em>\2</em>\3", t, flags=re.IGNORECASE | re.MULTILINE)
            ...
    return ans
```

**作用**：高亮字段是 `["content_ltks", "title_tks"]`（search.py:197）——分词字段才能让 ES 精确打 `<em>`。中文分词后 ES 打点准，直接用；**英文按整词边界手工重扫**（因为 ltks 是 whitespace 切碎的词，打点不准）。

## 五、索引映射 `conf/mapping.json` —— dynamic_templates 自动定型

`create_idx`（es_conn_base.py:120-127）加载 `conf/mapping.json` 建索引，**向量字段不用显式声明**——靠通配模板在首次写入时动态创建：

```json
"dynamic_templates": [
  { "int":   { "match": "*_int",  "mapping": { "type": "integer", "store": "true" } } },
  { "tks":   { "match": "*_tks",  "mapping": { "type": "text", "analyzer": "whitespace", "store": true } } },
  { "ltks":  { "match": "*_ltks", "mapping": { "type": "text", "analyzer": "whitespace", "store": true } } },
  { "kwd":   { "match_pattern": "regex", "match": "^(.*_(kwd|id|ids|uid|uids)|uid|id)$",
               "mapping": { "type": "keyword", "similarity": "boolean", "store": true } } },
  { "dt":    { "match_pattern": "regex", "match": "^.*(_dt|_time|_at)$",
               "mapping": { "type": "date", "format": "yyyy-MM-dd HH:mm:ss||...", "store": true } } },
  { "rank_feature": { "match": "*_fea", "mapping": { "type": "rank_feature" } } },
  { "dense_vector": { "match": "*_768_vec", "mapping": { "type": "dense_vector", "index": true,
                                                         "similarity": "cosine", "dims": 768 } } },
  { "dense_vector": { "match": "*_1024_vec", "mapping": { ... dims": 1024 } } },
  ...
]
```

**作用（关键）**：
- **字段后缀即类型**：`_tks` 分词、`_kwd` 关键词、`_dt` 日期、`*_vec` dense_vector——约定优于配置。
- **向量维度由 embedding 输出决定**：入库时 `vector_size = len(v)`（task_executor.py:757-762），查询时 `q_{len}_vec`——768/1024/1536 维自动匹配对应模板。
- 索引名统一 `ragflow_{tenant_id}`（search.py:45-46），**一个租户一个索引**，kb 靠 `kb_id` 字段过滤。

## 六、连接池 `@singleton` —— 全局共享一个 client（es_conn_pool.py）

```python
@singleton
class ElasticSearchConnectionPool:
    def __init__(self):
        for _ in range(ATTEMPT_TIME):                  # 启动重试 2 次
            try:
                if self._connect(): break
            except Exception as e:
                time.sleep(5)
        if int(self.info["version"]["number"].split(".")[0]) < 8:
            raise Exception("Elasticsearch version must be >= 8 ...")

    def _connect(self):
        self.es_conn = Elasticsearch(hosts, basic_auth=..., verify_certs=False, timeout=600)
        self.info = self.es_conn.info()
        return True

    def refresh_conn(self):                             # 断线续命
        if self.es_conn.ping(): return self.es_conn
        self.es_conn.close(); self._connect(); return self.es_conn

ES_CONN = ElasticSearchConnectionPool()                 # 模块级单例
```

**作用**：所有 `ESConnectionBase` 实例（普通检索 + memory 元数据索引各 new 一个）都调 `ES_CONN.get_conn()` 拿到**同一个 `Elasticsearch` client**；`search/insert/update` 遇 `ConnectionTimeout` 就 `_connect()` 续命重试（es_conn.py:328-331）。

## 七、数据流转示意

```
Dealer.search (rag/nlp/search.py:205)
  ├─ FulltextQueryer.question() ──▶ MatchTextExpr(content_ltks,title_tks,...)
  ├─ emb_mdl.encode_queries() ──▶ MatchDenseExpr("q_{dim}_vec", vec, cosine, topk, {similarity:0.1})
  ├─ FusionExpr("weighted_sum", weights="0.001,1")     # 只取向量权重
  └─ filters(kb_id/doc_id) + highlight_fields
                    ▼
ESConnection.search (es_conn.py:179)
  ├─ condition dict ──▶ bool_query.filter += Q(term/terms/range/available_int)
  ├─ MatchTextExpr ──▶ bool_query.must += Q(query_string, best_fields, minimum_should_match)
  │                    bool_query.boost = 1 - vector_similarity_weight
  ├─ MatchDenseExpr ──▶ s.knn("q_768_vec", k, k*2, query_vector=..., filter=bool_query.to_dict(), similarity=0.1)
  └─ s.query(bool_query).highlight(content_ltks,title_tks,fragment_size=50)
       .sort().source(select_fields)[offset:offset+limit] ──▶ s.to_dict()
                    ▼
ES 返回 hits（每 hit 含 _id/_score/_source/_highlight，<em> 由 ES 生成）
                    ▼
Dealer.search 收尾 (search.py:273-277)
  ├─ get_doc_ids / get_highlight(res, keywords, "content_with_weight")   # 英文手工重扫 <em>
  ├─ get_fields(res, src+["_score"])
  └─ SearchResult(total, ids, query_vector, field, highlight, keywords)
                    ▼
rerank（可选）: _knn_scores() 二次纯 KNN 取余弦分 ──▶ rerank_with_knn 混合 tks/vts
```

## 八、对照 ai_assistant

| RAGFlow | 你的 ai_assistant | 差距 |
|---------|------------------|------|
| DocStoreConnection 抽象门面 + 多引擎可插拔 | 直连单一存储 | ❌ 换库全改 |
| 表达式对象（Text/Dense/Fusion）翻译成 DSL | 裸 SQL/裸 API | ⚠️ 检索逻辑和存储耦合 |
| 向量字段通配模板自动定型 | 手动建索引 | ⚠️ 新向量维度要改 schema |
| 余弦阈值 `similarity` + 空结果重试 | 无 | ⚠️ 无结果时不会降级重试 |
| 高亮 `<em>` + 英文整词重扫 | 无 | ⚠️ 前端引用无高亮 |
| 单例连接池 + 断线续命 | 每次新建连接 | ⚠️ 高并发下连接爆炸 |

**落地优先级**：
- **P0**：把存储访问收敛到一个接口——`search(filters, match_text, match_dense, fusion)`，实现类里再做 SQL/HTTP 翻译。哪怕只有一个引擎，这个抽象也让你敢换。
- **P1**：向量检索加相似度阈值 + 空结果降级重试（放宽阈值再搜一次）。
- **P2**：结果高亮（`<em>`）——前端引用是 RAG 体验的一部分。

## 九、总结

| 环节 | 代码 | 作用 |
|------|------|------|
| 抽象接口 | `DocStoreConnection`（doc_store_base:148） | 检索/写库统一门面 |
| 表达式类 | MatchText/Dense/Fusion/OrderBy（58-145） | 跨引擎的检索描述 |
| 条件翻译 | condition→bool filter（es_conn:201） | term/terms/range |
| 全文翻译 | MatchText→query_string（246） | best_fields + 权重 |
| 向量翻译 | MatchDense→knn（253） | 余弦阈值 + bool 过滤 |
| 融合翻译 | Fusion→提取权重（236） | boost 压制全文 |
| 高亮 | get_highlight（es_conn_base:324） | `<em>` + 英文重扫 |
| 索引映射 | conf/mapping.json | 后缀约定 + 动态向量模板 |
| 连接池 | es_conn_pool | 单例 + 断线重建 |

**一句话心法**：**存储抽象 = 上层只写"检索意图"（表达式对象），下层只做"翻译成 DSL"，中间用条件字典和表达式对象解耦**。引擎可换、上层不动，这才是"可插拔存储"的本质——不是封装数据库，而是把检索语言和存储语言分开。
