# AI 数据问答层（数仓 + LLM）

让用户用**自然语言**查询数仓数据，不用学 SQL。

> 这是一份**学习用**的项目代码：注释面向小白，关键逻辑用 Mock 模拟，外部依赖用接口抽象。目的不是跑生产，而是理解"用户一句话 → 数仓里的一个数字"这条完整链路是怎么流转的。

---

## 一句话说清楚这个项目

用户问"**上个月逾期率是多少**"，系统经过一条流水线，最终回答"**3.2%，比上月上升 0.4 个百分点**"。

中间的每一步，就是这个项目要讲的。

---

## 整条链路（真实生产版）

```
用户："上个月逾期率是多少？"
   │
   ▼
① 意图识别     —— 这是要查数？还是问概念？（三类：指标查询/口径解释/血缘追溯）
   ▼
② Query改写    —— "上个月"→具体日期，"坏账率"→统一成"逾期率"
   ▼
③ RAG检索      —— 多路召回(向量+关键词+规则) → RRF融合 → 精排 → 权限过滤
   ▼
④ NL2SQL       —— 注入表结构，把话翻译成 SQL
   ▼
⑤ SQL校验      —— 安全检查：禁DROPP、必须有WHERE、限制行数
   ▼
⑥ 执行         —— 超时控制 + 行数限制 + 数据质量/账龄成熟度检查
   ▼
⑦ 结果解释     —— 把 0.032 翻译成"3.2%"，并附注意事项
   ▼
⑧ 审计         —— 全程记录（脱敏后异步写 Kafka）
```

## 目录结构

```
src/ai_assistant/
├── llm_client.py        # LLM 抽象层 + MockLLM（"万能插头"，换模型只改这里）
├── schema_catalog.py    # 指标口径 + 表结构（读 config/indicators.yaml）
├── intent_classifier.py # ① 意图识别 + 槽位抽取
├── query_rewriter.py    # ② Query改写（时间归一化、同义词映射、口径绑定）
├── retriever.py         # ③ RAG检索（多路召回 + RRF融合 + 精排 + 权限过滤）
├── sql_generator.py     # ④ NL2SQL（注入Schema生成SQL）
├── sql_validator.py     # ⑤ SQL校验（安全门）
├── query_executor.py    # ⑥ 执行（超时/行数/质量/成熟度）
├── result_explainer.py  # ⑦ 结果解释（翻译成人话 + 附注意事项）
├── audit_logger.py      # ⑧ 审计（脱敏 + 异步写日志）
└── pipeline.py          # 🎯 编排器（把上面所有模块串起来）
```

**建议阅读顺序**：先看 `pipeline.py`（了解全貌），再按 ①→⑧ 逐个模块看细节。

## 怎么跑

```bash
cd credit_risk_control_system
python3 scripts/demo_qa.py
```

它会模拟三个问题，展示三种不同的处理路径：

| 问题 | 意图 | 走的链路 |
|------|------|---------|
| 上个月逾期率是多少？ | 指标查询 | 完整链路（改写→检索→SQL→执行→解释） |
| 逾期率是什么意思？ | 口径解释 | 只走 RAG 直接回答 |
| 你吃了吗？ | 闲聊 | 直接让 LLM 回答 |

---

## 三个最值得理解的设计

1. **LLM 抽象层**：所有模块依赖 `LLMClient` 接口，不依赖某一家模型。换模型改一处，测试用 Mock。这就是"面向接口编程"。

2. **Schema 注入**：NL2SQL 生成前必须先拿到准确表结构，否则模型会瞎编字段名。这就是为什么有个 `schema_catalog.py`。

3. **安全门 + 降级**：SQL 执行前必须过校验（禁危险操作、防全表扫描）；意图识别置信度低时反问用户，不硬猜。**生产系统的核心不是"答得对"，而是"知道自己什么时候不该答"。**

---

## 和现有数仓的关系

这个模块**不重复造数仓**，而是复用现有的 `data/warehouse`（ODS/DWD/DWS/ADS 分层）。

它读取的指标口径定义在 `config/indicators.yaml`，字段名对齐现有的 `ads_delinquency_daily`、`ads_model_monitor_daily` 等 ADS 表。

## 学习建议

- 每个文件开头都有一段"小白类比"，先读那个，再读代码
- 行内注释只讲"为什么这么做"（why），不讲"这行在干嘛"（what）——这是生产级注释的习惯
- 跑通 `demo_qa.py` 后，试着改 `config/indicators.yaml` 加一个新指标，看链路会不会跟着变
