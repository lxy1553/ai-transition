# Bad Case 归因分析

> 用 `scripts/eval_qa.py` 真实跑出来的结果，不是编的。
> 当前（修复后）：评测集 50 题，意图识别准确率 **94%**（47/50），指标解析准确率 **100%**（36/36）。

面试时，最打动面试官的不是"我的系统 100% 对"，而是"我知道它哪里会错、为什么错、怎么改"。
这份文档记录了我从 70% 迭代到 94% 的完整过程，每一步都是真实的 bad case 驱动。

---

## 一、迭代过程（三次真实修复）

### 第 1 版：意图 72%，指标 86%

**问题**：MockLLM 硬编码了"逾期率""通过率""额度"三个词，不认识同义词。

**修复**：让 MockLLM 接收指标目录（catalog），靠查别名表识别同义词，不再硬编码。

### 第 2 版：意图 82%，指标 92%

**问题**：暴露了三个新的真实缺陷——
1. "什么是坏账率"里"是什么"三个字不连续（是"什么是"），匹配不到"口径解释"
2. "数据来源是什么"被误判成"口径解释"（因为先判了"是什么"，没先判"来源"）
3. "额度""逾期"这类简称，Mock 只做了 `别名 in query`，没做 `query in 别名`

**修复**：
1. 意图识别加"什么是"语序 + 调整判断顺序（血缘来源 > 口径解释 > 指标查询）
2. 加"计算逻辑""计算方式"到血缘追溯
3. Mock 改成双向包含匹配（`别名 in query` 或 `query in 别名`）

### 第 3 版（当前）：意图 94%，指标 100%

只剩 3 个 bad case，全部是"未知指标"边界（见下）。

## 二、剩下的 3 个 Bad Case（本质：意图识别和指标解析耦合）

| 编号 | 问题 | 预期 | 实际 |
|------|------|------|------|
| 33 | 查一个不存在的指标xyzabc | 指标查询 | 闲聊 |
| 34 | 收入是多少 | 指标查询 | 闲聊 |
| 40 | 帮我看看上个月的表现 | 指标查询 | 闲聊 |

### 根因：这是"意图识别"和"指标解析"耦合了

这三个问题有一个共性：用户**有"查数据"的动作**，但**查的指标不存在或太模糊**。

正确的系统行为应该是：
1. 意图识别回答"用户是不是想查数据"——"查""多少""是多少"这些**动作信号**
2. 指标解析回答"查的是什么指标、这个指标存不存在"——**这是另一个独立的步骤**

但当前 Mock 的意图识别靠"是否有指标同义词"来判断"是否指标查询"，
等于把"指标是否存在"耦合进了"意图识别"。指标不存在 → 判成闲聊。

### 为什么这是 Mock 的局限，不是真实缺陷？

真实 LLM 能区分"查的动作"和"指标是否存在"这两个概念：
- "查一个不存在的指标xyzabc"——LLM 看到"查"就知道是查询意图，然后发现 xyzabc 不是指标，在"指标解析"阶段反问
- Mock 做不到这种语义理解，只能靠"有没有已知指标词"来猜

### 修复方向（面试要能讲）

**解耦意图识别和指标解析**：
- 意图识别只看**动作信号**（"查""多少""是多少""帮我看看"），不依赖"指标名是否认识"
- 指标解析独立负责"查什么指标、存不存在"，不存在就反问

这背后的设计原则：**意图判断"想不想查"，解析判断"查什么"，两者是不同层次，必须解耦。**
真实系统里，意图识别用动作信号，指标解析用目录映射，不会把"指标不存在"误判成"用户不想查"。

### 另一个观察：case 40 "上个月的表现"

"表现"这个词太模糊，没有明确指标指向。这个 case 判成"闲聊/反问"其实**是合理的**，
因为系统不该瞎猜"表现"指什么。这是评测集标注的争议点——模糊问题该反问，不该硬答。

## 三、三条通用教训（贯穿整个迭代）

1. **同义词是长尾，别硬编码**——用别名表/向量检索兜底，Mock 查别名表，真实 LLM 靠语义
2. **精确匹配会漏**——简称、全称、口语变体（"什么是 X" vs "X 是什么"）都要处理，做双向包含匹配
3. **意图和指标解析要解耦**——意图判断"想不想查"，解析判断"查什么"，两者是不同层次

这三条，每一条都是真实生产里会踩的坑。能主动讲出"我为什么从 70% 迭代到 94%，
每一步修了什么、为什么"，比"我的系统很准"有说服力一百倍。

## 四、怎么跑真 LLM 评测

当前评测是 Mock 模式（免费、可复现，但测的是"链路对不对"，不是"语义理解准不准"）。

要测真实水平，设置 DeepSeek API Key 后重跑：
```bash
export DEEPSEEK_API_KEY=sk-你的key
python3 scripts/eval_qa.py   # 会自动切到真 DeepSeek
```

真 LLM 模式下，同义词、语序、未知指标这三个短板会大幅改善——
因为真实 LLM 靠语义理解，不靠关键词匹配。但真 LLM 有随机性（temperature），
建议把 temperature 设 0 再评测，保证结果可复现。
