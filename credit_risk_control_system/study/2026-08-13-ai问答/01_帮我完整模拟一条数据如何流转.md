# 提问：帮我完整模拟一条数据在 credit_risk_control_system 中如何详细流转

## 我的提问

> 就当我是小白，帮我完整模拟一条数据在 credit_risk_control_system 中如何详细流转，比如用户进来一个问题，我们公司上个月环比逾期率变化是多少 /grill-me

## 回答

先纠正一个认知：你问的"**上个月环比逾期率变化是多少**"不是实时决策场景，而是**数据问答场景**。它不经过 `inference_pipeline`（那是用户来贷款时打分用的），它查的是数仓 ADS 层里一张叫 `ads_delinquency_daily`（逾期率日报）的表。

所以这条数据要讲两条腿：
- **第 1 条**：逾期率这个数字是**怎么被算出来的**（数据血缘，从源头到 ADS）
- **第 2 条**：你提问后，系统**怎么把这条数据找出来回答你**（Agent 问答链路）

下面按小白视角，一步步走。

## 第 2 条腿先讲：逾期率这个数字是怎么来的？

这是**数据血缘**，是理解整个系统的关键。逾期率不是凭空冒出来的，它是从每一个用户的真实行为一点点加工出来的。

### 源头：用户的行为事件（真实世界）

想象一个用户小张在 App 上操作，产生了三类原始数据：

| 事件 | 落到哪张原始表 | 例子 |
|------|--------------|------|
| 小张填了贷款申请 | `ods_application`（申请表） | 申请金额、收入、设备号、城市... |
| 小张在 App 里点来点去 | `ods_user_behavior`（行为埋点） | 页面浏览、输入、提交... |
| 小张的还款情况 | `ods_repayment`（还款记录） | 应还金额、实还金额、是否逾期... |

### 第 1 站：ODS 层 —— "原封不动的快递盒"

ODS（原始数据层）的原则是：**业务系统来什么，我就存什么，一个字都不改**。所以这里充满了脏数据：

```python
# ods_application 里的真实状态（故意造的脏数据）
apply_amount = [-1000, 0, None, 5000, ...]      # 有负数、有空值！
product_type = ['cash_loan', 'UNKNOWN_TYPE', ...] # 有非法值！
user_name    = '张三'        # ⚠️ 明文姓名，还没脱敏
id_card      = '110101199003071234'  # ⚠️ 明文身份证
phone        = '13812345678'  # ⚠️ 明文手机号
```

> 小白类比：ODS 就像快递分拣站的收货区——包裹原样堆着，不拆不验，怕的就是"我动了数据，回头说不清原始状态长啥样"。

### 第 2 站：DWD 层 —— "把脏东西洗干净"

DWD（明细数据层）开始加工，每张表对应 ODS 一张表：

| 加工动作 | 例子 |
|---------|------|
| **脱敏** | `张三` → `张*`，身份证 → `1101**********34` |
| **修正脏数据** | `apply_amount = -1000` → `0`（负数不合理） |
| **标准化** | `UNKNOWN_TYPE` → 映射到标准字典 |
| **打质量分** | 每条数据算一个 `dq_score`，低于 60 分的标记为"疑似脏数据" |

```python
# data_lineage.yaml 里记录的血缘
ods_application → dwd_application
  user_name/id_card/phone/ip → 脱敏(mask)
  apply_amount → 负数/空值修正为0
  NEW: dq_score = 100 - 扣分项        # 新增质量分
  NEW: dq_quarantined = dq_score < 60  # 新增"是否隔离"标记
```

### 第 3 站：DWS 层 —— "把一个用户的所有信息捏成一张卡片"

DWS（汇总层）是整个数仓的**核心**。它把三张 DWD 明细表，**按用户聚合**成一张"用户风险特征宽表"：

```
3 张 DWD 明细表（一个人几十条记录）
  dwd_application   —— 申请记录
  dwd_user_behavior —— 行为埋点（滑动窗口聚合）
  dwd_repayment     —— 还款记录
        │
        │  groupby(user_id) + 时间窗口 + 三表 left join
        ▼
1 张宽表（一个人一行）：user_risk_feature_wide
  特征: apply_amount_avg, apply_cnt_7d, night_ops_ratio_30d,
        overdue_cnt_hist, on_time_rate, ... 共17维
```

**关键点**：`night_ops_ratio_30d`（近30天夜间操作占比）这种特征，是从行为埋点里按**时间窗口**算出来的——只看 `event_time` 在近 30 天内的记录，算晚上 22 点到凌晨 5 点操作的占比。

### 第 4 站：ADS 层 —— "直接给业务用的成品"

ADS（应用数据层）不再做复杂加工，**预聚合、即查即用**。这里有一堆成品表，其中就有你问的逾期率：

```
ads_delinquency_daily（逾期率日报）★ 你要的这张
ads_model_monitor_daily（模型监控日报）
ads_portfolio_analysis（资产组合分析）
ads_training_samples（训练样本集）
```

**逾期率到底怎么算？** 看 `build_delinquency_daily` 的代码：

```python
# 逾期率 = 坏样本数 / 总样本数
daily['delinquency_rate'] = bad_loans / total_loans
```

而"坏样本"（`label=1`）是**30 天之后**才定性的——这就是关键的 **PIT 原则**：

> 一个用户 7 月 1 日申请贷款，**7 月 1 日的特征**去预测**8 月 1 日（T+30）是否逾期**。逾期了 label=1，没逾期 label=0。
>
> ⚠️ 如果拿 8 月 1 日的特征去判断 7 月 1 日的申请，就是**时间泄漏**——你已经知道答案了还预测什么？

### 血缘全图（把第 2 条腿串起来）

```
真实世界                           数仓
────────                           ────────
用户申请/行为/还款                    ODS 层            DWD 层              DWS 层              ADS 层
用户贷款申请 ──binlog/上报──►       ods_application ──清洗──► dwd_application ──聚合──► 用户风险特征宽表 ──加标签──► ads_delinquency_daily
用户App行为 ──SDK埋点──►          ods_behavior   ──► dwd_behavior  ──► (17维)      ──► ★逾期率日报
用户还款    ──binlog──►           ods_repayment  ──► dwd_repayment ──►
```

## 第 1 条腿：你的问题怎么被系统"听懂"并"查出"数据

现有代码里，实时决策链路（`inference_pipeline`）是完整的，但**问答链路需要补 Agent/NL2SQL 层**。

### 步骤 ①：意图识别 —— Agent 判断你想干什么

LLM 判断你的问题属于哪类：命中"**离线指标查询**"，走 NL2SQL。

### 步骤 ②：NL2SQL —— 把人话翻译成 SQL

Agent 带着 **Schema Catalog**（表结构清单）让 LLM 生成 SQL。关键约束：必须注入表结构，否则模型会编造字段名。

```sql
-- LLM 生成的 SQL（必须带 dt 分区过滤）
SELECT DATE_FORMAT(label_date, '%Y-%m') AS month,
       ROUND(SUM(label) / COUNT(*), 4) AS delinquency_rate
FROM ads.delinquency_daily
WHERE label_date >= '2026-06-01'
GROUP BY DATE_FORMAT(label_date, '%Y-%m')
ORDER BY month;
```

### 步骤 ③：安全校验 —— 不能乱跑

执行前过 5 道检查（面试亮点）：危险操作、分区过滤、行数限制、权限、JOIN 限制。

### 步骤 ④：执行 → 拿到结果 → LLM 回答

```
执行结果:
  2026-06  逾期率 3.2%     （上月）
  2026-05  逾期率 2.8%     （上上月）

LLM 翻译成人话:
  "公司上个月（6月）逾期率 3.2%，比上月（5月）的 2.8% 上升了 0.4 个百分点，
   环比上升约 14%。需要重点关注。"
```

## 关键概念速查（小白必懂）

| 概念 | 一句话理解 |
|------|-----------|
| **ODS/DWD/DWS/ADS** | 数据加工的 4 个车间：原样收 → 洗干净 → 揉成团 → 做成成品 |
| **血缘 (Lineage)** | 每个数字都能追溯到它从哪个源头算出来的 |
| **PIT 原则** | 只用"过去"的信息预测"未来"，防止偷看答案 |
| **label / 标签** | 这笔贷款 30 天后有没有逾期（0=没逾期，1=逾期） |
| **环比** | 这个月跟上个月比（vs 同比：这个月跟去年同月比） |
| **NL2SQL** | 把自然语言翻译成 SQL，让业务人员不用学 SQL 也能查数 |
