```
    ├── result_explainer.py         # ⑦ 结果解释
    ├── audit_logger.py             # ⑧ 审计（脱敏）
    └── pipeline.py                 # 🎯 编排器
```

### 整条链路（真实生产版）

```
用户："上个月逾期率是多少？"
  → ① 意图识别（指标查询/口径解释/血缘追溯/闲聊）
  → ② Query改写（"上月"→日期，"坏账率"→逾期率）
  → ③ RAG检索（多路召回+RRF融合+精排+权限过滤）
  → ④ NL2SQL（注入Schema生成SQL）
  → ⑤ SQL校验（禁DROP、必须有WHERE、限制行数）
  → ⑥ 执行（超时+行数+质量/账龄检查）
  → ⑦ 结果解释（0.032→3.2%+注意事项）
  → ⑧ 审计（脱敏后异步写日志）
```

### 演示结果（三个意图正确分流）

| 问题 | 意图 | 结果 |
|------|------|------|
| 上个月逾期率是多少？ | 指标查询 | 完整链路 → "3.2%，比上月上升0.4pp" + 账龄成熟度提示 |
| 逾期率是什么意思？ | 口径解释 | RAG 直接返回指标定义 |
| 你吃了吗？ | 闲聊 | 置信度低，反问用户 |

### 三个核心设计（面试能讲）

1. **LLM 抽象层**：面向接口编程，换模型改一处，测试用 Mock
2. **Schema 注入**：NL2SQL 前先拿表结构，防止模型瞎编字段
3. **安全门 + 降级**：SQL 执行前过 5 道校验；置信度低反问不硬猜

### 调试过程

运行 demo 时遇到两个问题并修复：
1. Python 3.9 不支持 `str | None` 语法 → 改成 `Optional[str]`
2. MockLLM 最初检查整个 prompt（而 prompt 模板里含示例词），导致误判 → 改成提取"用户问题"那一句再判断
