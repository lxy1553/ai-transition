# 提问：先具体讲讲这个解耦意图识别和指标解析再进行推进

## 我的提问

> 先具体讲讲这个解耦意图识别和指标解析再进行推进

## 回答

这是值得讲透的设计问题。先讲清"为什么耦合是错的"，再动手。

### 一、两个完全不同的"理解层次"

NLP 经典模型 **Intent + Slot（意图 + 槽位）** 把一句话拆成两个独立问题：

| 层次 | 回答的问题 | 例子 |
|------|-----------|------|
| **意图 (Intent)** | 用户想干什么？ | 查数 / 问概念 / 查来源 / 闲聊 |
| **槽位 (Slot)** | 对象是谁？ | 指标=逾期率、时间=上个月 |

经典例子："帮我订一张明天去北京的机票" → 意图=订票，槽位={目的地:北京, 时间:明天}。判断"想订票"（意图）根本不需要先知道"目的地是不是真实城市"（槽位解析）。

### 二、你现在的代码哪里耦合了

```python
if "多少" in query or "查" in query:   # 动作信号
    return 指标查询
if self._find_indicator(query) is not None:   # ← 指标信号（耦合点）
    return 指标查询
```

`_find_indicator(query) is not None` 把"有没有已知指标"当成了"是不是查询意图"的判断依据，导致"指标不存在"反向污染"意图判断"：

| 问题 | 用户真实意图 | 耦合时的判断 |
|------|------------|------------|
| 查一个不存在的指标xyzabc | 想查数（有"查"） | 闲聊 ❌ |
| 收入是多少 | 想查数（有"是多少"） | 闲聊 ❌ |

### 三、正确的解耦方案

意图识别只看**动作信号**，指标解析才看**指标信号**：

```
意图识别：用户想查数吗？→ 看动作（"多少""查""是多少"），不看指标存不存在
指标解析：查的是哪个指标？→ 看指标目录，指标不存在 → 反问，但意图已经对了
```

### 四、但动作信号不能乱选

| 动作词 | 风险 |
|--------|------|
| "怎么样" | ❌ 会误判"今天天气怎么样" |
| "看看" | ❌ 会误判"看看天气" |
| "帮我" | ❌ 会误判"帮我写首诗" |
| **"多少"/"是多少"/"查"/"查询"** | ✅ 精准，闲聊里几乎不出现 |

同时保留指标信号作辅助（陈述式查询如"最近30天的逾期率"没动作词但有指标名）。

---

## 实现 + 结果

加了 `_has_query_action(query)` 方法，意图识别改成：

```python
# 解耦关键：动作信号（想查数） OR 指标信号（陈述式查询）
if self._has_query_action(query) or self._find_indicator(query) is not None:
    return "指标查询"
```

**评测结果**：意图识别 **98%**（49/50），指标解析 **100%**（36/36）。

只剩 1 个 bad case：`case 40 "帮我看看上个月的表现"`——"表现"太模糊，系统判"闲聊→反问"其实是**正确的产品行为**（模糊问题该反问，不该硬猜），是评测标注过严，不是系统缺陷。

**解耦带来的设计原则**：意图判断"想不想查"，解析判断"查什么"，两者是不同层次，必须解耦。真实系统里意图识别用动作信号，指标解析用目录映射，两者独立演进、独立测试、独立失败。
