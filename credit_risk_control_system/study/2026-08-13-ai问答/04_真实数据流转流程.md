# 提问：真实数据流转流程是如何的

## 我的提问

> 先这样，先说关于上面一个数据流转吧，这个项目不是正式落地项目，是模拟数据，我就是想问下真实数据流转流程是如何的，一步一步来，从问题的意图识别到改写，到 rag 查询中所有细节，如果不支持问环比，就问比如上个月逾期率是多少，/grill-me

## 回答（grilling：数据流转模拟 vs 真实生产）

先承认一件事：之前那份讲解**大部分是项目代码里不存在的东西**。模拟项目为了能跑通，把真实生产里最难的环节全抹平了。下面先把失真的地方逐条打穿，再给真实链路。

---

## 致命伤 ①：真实生产里，"意图识别"不是 LLM 随便判断一下

| 模拟版 | 真实生产版 |
|--------|-----------|
| 一次 LLM 调用，输出意图数字 | **两级流水线**：先用轻量意图分类模型/规则（FastText、BERT 小模型，几 ms）粗分，拿不准才升级到 LLM |
| 没有任何兜底 | 兜底链：规则命中 → 小模型 → 大模型 → 人工，逐级降级 |
| 意图就 4 类 | 意图是多层结构：主题域（信贷/存款/报表）→ 意图（指标查询/口径解释/血缘）→ 槽位（指标名、时间、维度） |

真实里"上个月逾期率"，系统先切到"信贷主题域"，再分类"指标查询"，再抽槽位：`指标=逾期率，时间=上月`。每步都可能错，所以每步都带置信度阈值，低于阈值就反问，不硬猜。

## 致命伤 ②：Query Rewrite 我完全没讲，而它是必过的一关

真实链路里用户原话几乎从不直接进检索。"上个月"是哪个月份？"逾期率"对应哪个指标？这一步叫 **Query Rewrite（查询改写）**：

```
用户原话："上个月逾期率是多少"
   ↓ Query Rewrite
标准查询："近一个月(2026-06-01~2026-06-30) 的 DPD30+ 逾期率"
   ↓ 拆结构化请求
{指标: "逾期率", 口径: "DPD30+", 时间: ["2026-06-01","2026-06-30"]}
```

改写的核心动作：时间归一化（"上个月"→具体日期区间）、同义词映射（"坏账率"→统一指向 delinquency_rate）、消歧（笔数 vs 金额口径）。

## 致命伤 ③：RAG 查询的真实流程比"查文档"复杂得多

```
改写后的 query
  → ① 检索召回（多路并行）：向量检索 + 关键词检索(BM25) + 规则字典检索
  → ② 融合排序（RRF）：多路结果合并、去重
  → ③ Rerank 精排：用更贵的模型重排 top 20 → top 5
  → ④ 权限过滤：这个用户能看哪些指标/表？
  → ⑤ 注入上下文：拼接成 {指标定义 + 表结构 + 历史口径}
```

第④步权限过滤在金融场景是生死线——不是所有分析师都能看所有逾期口径。

## 中伤 ④：环比查询在真实生产里通常不支持直接问

"环比" = 本月 - 上月，再归一化 = 跑两次查询再算算术。生产里两种做法：
1. 查一次本月，结果解释层补充"相比上月"
2. 指标平台预计算好环比字段（mom_change）直接查

**关键**："环比"是衍生指标不是基础指标。数据问答系统优先保证基础指标查得准，衍生计算交给上层。所以退化为"上个月逾期率是多少"是对的——一次查询，一个确定性答案。

## 中伤 ⑤：SQL 生成不是一次成型，是"生成→校验→修正"循环

```
LLM 生成 SQL → 校验器检查 → 失败带着错误信息重新生成（最多 N 次）→ 仍失败 → 拒答+提示
```

而且 SQL 不是从零写，先用 RAG 拿到准确表结构（Schema），再在这个 Schema 约束下生成，字段名不可能编造。

---

## 真实生产全链路（修正版，10 步）

以"上个月逾期率是多少"为例：

```
① 网关层（API Gateway）— 鉴权、限流、request_id 生成
② 意图识别（两级：小模型→LLM）— 主题域/意图/槽位
③ 查询改写（Query Rewrite）— 时间归一化、口径绑定、结构化请求
④ RAG 检索（多路→RRF→Rerank→权限过滤）— 拿指标定义、表结构
⑤ NL2SQL（Schema 约束下生成）— SELECT SUM(bad_loans)/SUM(total_loans)...
⑥ SQL 校验（语法+权限+分区+危险操作）
⑦ 执行（超时、行数上限）→ 3.2%
⑧ 质量检查（dq_quarantined 比例，账龄成熟度校验）
⑨ 结果解释（LLM）— "6月逾期率3.2%，较5月2.8%上升0.4pp"
⑩ 审计 + 监控 — Kafka 日志、指标上报、异常告警
```

**本质差别**：真实链路每一步都有"拿不准就降级/反问/拒答"的机制，模拟版每一步都是"直接给答案"。真实系统的核心不是"答得对"，而是"知道自己什么时候不该答"。
