# 真实生产链路与 8 个硬伤（grill-me 拷问结果）

> 背景：我（AI）先给了一份"数据流转模拟讲解"，然后用 grill-me 对自己开火，
> 挖出了 8 个硬伤。这份文档记录这些硬伤 + 修正后的真实生产链路。

---

## 一、8 个硬伤（按严重度排序）

### 🔴 硬伤 1：SQL 是错的，而且自相矛盾

讲解第 2 条腿刚说完 `ads_delinquency_daily` 里存的是预聚合字段 `total_loans` 和 `bad_loans`，
第 1 条腿的 SQL 却去 `SUM(label) / COUNT(*)`。

- 表名错：写的是 `ads.delinquency_daily`，真实是 `ads_delinquency_daily`
- 字段串：`label` 是 `ads_training_samples` 里的字段，根本不在逾期率日报表里

**正确 SQL**：
```sql
SELECT SUM(bad_loans) / SUM(total_loans) AS delinquency_rate
FROM ads_delinquency_daily
WHERE label_date >= '2026-06-01';
```

### 🔴 硬伤 2：时间口径 —— "上个月的逾期率"根本查不出来

逾期率是 **T+30 才定性**的。6 月放的贷，要 7 月底才满 30 天观察期。7 月底问"6 月逾期率"，
样本还没成熟，逾期没完全暴露，查出来是**不成熟的数字**。

> 面试必考的 **vintage / 账龄成熟度**，讲解里只字未提。

### 🔴 硬伤 3：根本没算"环比"

SQL 只查出两个月各自的逾期率，环比计算甩给了 LLM。生产里应该由查询层算好：
```
环比 = (本月逾期率 - 上月逾期率) / 上月逾期率
```

### 🟠 硬伤 4：账龄不齐导致环比是统计假象

环比上升可能不是真恶化，而是：
- 上月样本里，5 月初放贷的成熟度 > 6 月末放贷的成熟度
- 更成熟的池子自然逾期率更高

**正确做法**：按放贷月的 vintage 曲线对比（同账龄比），或限定"满 30 天观察期"的样本再比。

### 🟠 硬伤 5：口径歧义没讲

"逾期率"有两个口径：
- **笔数逾期率**：逾期笔数 / 放贷笔数
- **金额逾期率**：逾期金额 / 放贷金额

同一批数据两个口径结果不同。真实系统应**先走 RAG 查口径定义**，而不是直接跑 SQL。

### 🟡 硬伤 6：数据质量影响答案，漏了

DWD 层有 `dq_score` 和 `dq_quarantined`。如果某天数据质量差、大量样本被隔离，
逾期率会失真偏低。回答前应该先检查 dq 状态。

### 🟡 硬伤 7：实时 vs 离线边界没说清

"上个月"是离线日报（T+1，Spark 每天凌晨跑）。但"截至现在"是另一条实时链路（Flink→Redis）。
讲了离线却没说边界，等于埋了"追问就崩"的雷。

### 🟡 硬伤 8：漏了监控联动

`ads_model_monitor_daily` 的 alert_rules 有 approval_rate 异常告警。
真实生产里，逾期率环比异常应自动进监控触发告警，而不是等用户来问。

## 二、修正后的真实生产全链路（10 步）

以"**上个月逾期率是多少**"为例（"环比"退化为"基础指标查询"，因为环比是两步运算的衍生指标）：

```
① 网关层（API Gateway）
   鉴权、限流、request_id 生成（全程追踪）

② 意图识别（两级：小模型→LLM）
   主题域=信贷，意图=指标查询，槽位={指标:逾期率, 时间:上月}

③ 查询改写（Query Rewrite）
   时间归一化 → 6月1日~6月30日
   口径绑定 → DPD30+ 笔数逾期率
   结构化请求 → {指标, 口径, 时间, 维度:[]}

④ RAG 检索（多路 → RRF 融合 → Rerank → 权限过滤）
   拿到: 逾期率定义、计算口径、所属表 ads_delinquency_daily

⑤ NL2SQL（Schema 约束下生成）
   SELECT SUM(bad_loans)/SUM(total_loans) ...
   FROM ads_delinquency_daily WHERE label_date BETWEEN ... AND ...

⑥ SQL 校验（语法+权限+分区+危险操作）→ 通过

⑦ 执行（带超时、行数上限）→ 拿到 3.2%

⑧ 质量检查（dq_quarantined 比例，账龄成熟度校验）→ 达标

⑨ 结果解释（LLM）
   "6月逾期率3.2%，较5月2.8%上升0.4pp"

⑩ 审计 + 监控
   全链路日志写 Kafka，指标上报，异常触发告警
```

## 三、本质差别（小白最易误解的点）

| 模拟版 | 真实生产版 |
|--------|-----------|
| 每一步"直接给答案" | 每一步有"拿不准就降级/反问/拒答" |
| 一次 LLM 调用判意图 | 两级流水线（小模型→LLM） |
| 生成一次 SQL 就执行 | 生成→校验→修正循环 |
| RAG 只是"搜一下" | 多路召回→RRF→Rerank→权限过滤 |

> **真实系统的核心不是"答得对"，而是"知道自己什么时候不该答"。**
